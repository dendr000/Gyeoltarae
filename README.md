# 결타래

나무위키 스타일 커스텀 문법으로 세계관·설정을 정리하는 로컬 위키/메모 데스크톱 앱 (Electron + React).
아래아한글처럼 로컬 파일(.md)에 직접 저장하며, 서버나 계정 없이 오프라인으로 동작합니다.

> 예전 이름은 WikiDesk였습니다. 워크스페이스 안 내부 폴더명(`.wikidesk-data` 등)과 로컬 설정
> 저장 위치는 기존 사용자의 데이터가 끊기지 않도록 일부러 그대로 두었습니다.

## 개발 실행

```bash
npm install
npm run electron:dev
```

렌더러(React UI)만 브라우저에서 미리 보려면:

```bash
npm run dev
```

이 경우 실제 파일시스템 대신 `src/lib/mockApi.js`의 예시 데이터로 동작합니다.

## exe 빌드

이 프로젝트가 개발된 PC에서는 `electron-builder`가 Windows 환경 이슈(`EPERM: rename win-unpacked.tmp`)로
막혀서 `@electron/packager` 기반 스크립트를 기본으로 씁니다. 다른 PC에서는 `dist:win`이 될 수도 있습니다.

```bash
npm run dist:win:packager   # 권장 — release-packager\Gyeoltarae-win32-x64\Gyeoltarae.exe 생성 + 루트에 바로가기(결타래.lnk) 자동 생성
npm run dist:win            # electron-builder (nsis 설치파일 + portable) — 환경에 따라 실패할 수 있음
```

## 문법

**진짜 나무위키 문법** (그대로 복사해서 namu.wiki에 붙여넣어도 대부분 동작):

| 문법 | 결과 |
|---|---|
| `=제목=` ~ `======제목======` | 제목 1~6단계 — 제목 오른쪽에 나무위키처럼 `[편집]` 링크가 자동으로 붙음. 실제 나무위키처럼 별도 편집 페이지로 가는 게 아니라(결타래는 문서 전체가 하나의 편집창이라 그런 개념이 없음), 편집창이 보이는 모드로 전환되고 그 제목 위치로 커서가 이동함 |
| `'''굵게'''` / `''기울임''` | 굵게 / 기울임 |
| `__밑줄__` / `~~취소선~~` | 밑줄 / 취소선 |
| `^^위첨자^^` / `,,아래첨자,,` | 위·아래 첨자 |
| `{{{+1 텍스트}}}` ~ `{{{+5}}}` / `{{{-1}}}` ~ `{{{-5}}}` | 글자 크기 |
| `{{{#색상 텍스트}}}` | 글자 색 (`{{{#e91e63 ...}}}`, `{{{#red ...}}}`) |
| `[* 각주 내용]` | 자동 번호 매김 각주 — 번호를 누르면 각주 목록으로 이동, 목록의 "↩"를 누르면 원래 위치로 돌아감 |
| `[br]` | 명시적 줄바꿈 — 문단이나 각주 안에서 그냥 줄바꿈을 쳐서는 반영이 안 될 때 씀 |
| `* 항목` (중첩 `**`, `***`) / `1. 항목` | 목록 — 항목 다음 줄에 다른 문법 없이 텍스트만 오면(빈 줄로 끊기 전까지) 그 항목이 계속되는 걸로 봄(줄바꿈 이어쓰기) |
| `> 인용` (중첩 `>>`) | 인용/들여쓰기 |
| `||칸||칸||` + `<-2>`(가로병합) `<|2>`(세로병합) `<:>``<(>``<)>`(정렬) `<bgcolor=#fff>` `<nopad>`(셀 안쪽 여백 제거) | 표 |
| `<table align=left>` / `<table align=right>` | 표를 진짜로 띄움(CSS `float`) — 이후 내용이 표 옆으로 흘러 들어감. 멈추려면 `[clearfix]`. `align=center`는 그냥 가운데 정렬(float 아님) |
| `|표 제목|` (표 바로 위/아래 줄) | 표 캡션 |
| `{{{ 코드 }}}` | 코드블록 |
| `{{{#!syntax 언어}}}` | 코드블록 + 언어 이름 표시 (실제 색깔 강조는 없음) |
| `{{{#!folding 제목 ... }}}` | 접기/펼치기 |
| `----` ~ `-------` (대시 4~7개) | 구분선 굵기 4단계 |
| `[목차]` | 자동 목차 |
| `[clearfix]` | `<table align=left\|right>`로 띄운 표 옆으로 내용이 계속 흘러 들어가는 것을 멈춤 |
| `## 코멘트` / `##@ 코멘트` | 편집기 전용 숨김 노트 — 원문(에디터)에는 남지만 렌더링에는 전혀 안 나타남 |
| `[anchor(이름)]`, `[[#이름]]`, `[[문서명#이름]]` | 문서 내/문서 간 특정 위치로 이동 — `[[#제목]]`/`[[문서명#제목]]`은 그 문서의 실제 제목 텍스트와 매칭되고, 제목이 아닌 임의 지점을 가리키려면 먼저 `[anchor(이름)]`으로 이름표를 붙여두면 됨 |
| `[[문서명]]` / `[[문서명\|표시명]]` | 위키링크 — 클릭하면 그 문서로 이동. 문서가 없으면 점선으로 표시되고 클릭 시 그 이름으로 새 문서를 만듦(지금 문서와 같은 폴더에). 같은 이름(또는 번호를 뗀 이름, 또는 별칭)의 문서가 여러 개면 점선 밑줄로 표시되고 클릭 시 고를 수 있음. "0891 치고마"처럼 이름 앞에 순서 번호가 붙은 문서는 번호 없이 `[[치고마]]`라고만 써도 찾아지고, 그 문서 자체가 없어도 다른 문서 안에 `[[별칭:치고마]]`가 선언돼 있으면 그 문서로 연결됨(나무위키처럼 진화 전 단계용 빈 문서를 따로 안 만들어도 됨). 두 경우 모두 `]]`를 입력하는 순간(또는 그 안에서 Enter를 눌러도 — 줄바꿈 대신 `]]` 밖으로 나가며 바로 실행됨) 실제 파일명으로 자동 치환되고, 직접 `\|표시명`을 안 썼다면 번호 없는 깔끔한 이름이 표시명으로 자동으로 붙음(`[[치고마]]` 또는 `[[우라오스]]` 모두 → `[[0892 우라오스\|우라오스]]`) (역링크는 아직 미구현, 2차 예정) |
| `[[분류:이름]]` / `[[분류:이름\|출력명]]` | 분류 지정 — 문서 맨 아래 분류 배지로 모이고, 분류 페이지(상위/하위 분류 + 문서 목록)는 워크스페이스 트리와 분리된 전용 "분류" 공간(`.wikidesk-categories`)에 저장됨. `\|출력명`을 붙이면 배지에 보이는 글자만 바뀌고 분류 자체는 그대로 `이름` 기준 |
| `{{{#!wiki style="..."}}}` | 자유 스타일 박스 (그라데이션/그림자/테두리 등) — 안전한 CSS 속성만 허용하는 화이트리스트로 필터링됨. `lang="ko/ja/zh"`(언어 지정), `tag="span"`(줄바꿈 없는 인라인 박스로), `class="이름"`(아래 `{{{#!style}}}`로 선언해 둔 클래스 재사용) 속성도 함께 쓸 수 있음 |
| `{{{#!style\n.이름 { 속성: 값; }\n}}}` | 재사용 가능한 CSS 클래스 선언 — 문서 어디에 적어도 되고, 위 `{{{#!wiki class="이름"}}}`이나 표의 `<rowclass=이름>`/`<tableclass=이름>`으로 불러다 씀. 선택자는 `.클래스이름` 형태만 허용(다른 선택자는 조용히 무시됨), 다른 문서로 새 나가지 않도록 이 문서 안에서만 적용됨 |
| `{{틀:이름}}` / `{{틀:이름\|매개변수=값}}` / `[include(이름)]` / `[include(이름, 매개변수=값)]` | 틀 호출 — 이름=값·위치 인자 모두 지원, `[include(틀:이름, ...)]`처럼 이름에 `틀:` 접두사가 붙어있어도 인식(실제 나무위키 문서를 그대로 복사해오면 흔함). 표처럼 블록 요소가 있는 틀은 그 줄에 단독으로 호출해야 함(한 줄 안에서 다른 텍스트와 섞어 쓰면 첫 줄만 그 텍스트에 붙어버림 — 실제 나무위키와 동일). 틀 문서 자체는 워크스페이스 트리와 분리된 전용 "틀" 공간(`.wikidesk-templates`)에 저장됨. 단, `[include(...)]`는 실제 나무위키와 달리 임의 문서가 아니라 틀 공간만 대상으로 함 |
| `@매개변수@` / `@매개변수=기본값@` (틀 문서 안) | 실제 나무위키 틀 매개변수 문법. 값을 아예 안 넘기면 기본값, 빈 문자열로 넘기면(`이름=,`) 빈 문자열(기본값 아님) — `{{{매개변수}}}`/`{{{매개변수\|기본값}}}`도 하위 호환으로 계속 지원 |
| `{{{#!if 조건식 \n 내용 \n }}}` (틀 문서 안) | 조건부 블록(실제 나무위키 문법) — 조건식이 참(에 준하는 값 포함)이면 내용이 나옴. 지원: 대입(`=`, `;`로 여러 문장 연결), 비교(`== != < <= > >=`), 논리(`&& \|\| !`), 산술(`+ - * / %`), 단항(`! - +`), 삼항(`?:`), 소괄호, `this.매개변수`. 미지원: `**`, 증감연산, 비트연산, 문자열 메서드, 전역 함수, 배열·객체, `<rowif>`, 복합 대입 — 쓰이면 그 블록만 조용히 숨겨짐 |

**결타래 전용 확장** (나무위키에 붙여넣으면 문자 그대로 깨져 보임 — 이 앱에서만 쓸 문서라면 OK):

| 문법 | 결과 |
|---|---|
| `**굵게**` / `*기울임*` | 마크다운 스타일 강조 (`'''`/`''`의 별칭) |
| `--취소선--` | 취소선 (`~~~~`의 별칭) |
| `||=헤더=||` | 표 헤더 셀(`<th>`) 지정 — 표 편집기의 "헤더 행" 옵션은 이 대신 실제 나무위키 문법(`'''굵게'''`)으로 저장됨 |
| `[[자료:유형/이름]]` (그 줄에 단독으로) | 기술·특성처럼 재사용할 데이터를 정보 카드로 불러옴 — 나무위키 틀(`{{틀:...}}`)과 달리 결타래 전용 문법. 데이터 자체는 `필드: 값` 형식으로 워크스페이스 트리와 분리된 "자료" 공간(`.wikidesk-data`)에 저장됨 |
| `[[별칭:이름]]` | 검색 전용 별칭(예: "치고마"를 그 최종 진화형인 "우라오스" 문서의 별칭으로) — 화면엔 안 보이고, 제목·내용 검색에서 이 이름으로 찾으면 이 문서가 나옴. 나무위키의 `#redirect`처럼 별도 문서로 이동하는 게 아니라 항상 이 원본 문서를 계속 편집하게 됨 |
| `[[파일:이름]]` / `[[파일:이름\|너비]]` (그 줄에 단독으로) | 등록해 둔 이미지를 실제로 그려줌(너비는 `300px`/`50%`처럼 안전한 길이 값만 허용, 생략하면 원본 크기). 사이드바 "이미지" 공간의 "+"나 에디터 툴바의 "이미지" 버튼으로 실제 파일을 먼저 가져와야 함(분류/자료처럼 이름만 미리 적어두는 방식이 아님) — 이미지 자체는 워크스페이스 트리와 분리된 "이미지" 공간(`.wikidesk-images`)에 저장됨. `\|link=문서명`(또는 `\|link=문서명#제목`)을 추가하면 클릭 시 그 문서(그리고 필요하면 특정 위치까지)로 이동하는 링크가 됨 — 너비와 순서 상관없이 같이 쓸 수 있음(`\|300px\|link=문서명`) |
| 색상을 쓰는 자리에 `색1,색2` (예: `<bgcolor=색1,색2>`, `{{{#!wiki style="color:색1,색2"}}}`) | 라이트/다크 모드별로 다른 색 지정 — CSS `light-dark()`로 렌더링되어 지금 화면 테마에 맞는 쪽이 자동으로 적용됨. `{{{#글자색,#배경색 텍스트}}}`처럼 쉼표가 이미 다른 뜻(글자색,배경색)으로 쓰이는 자리는 예외 |

줄 전체가 `#태그1 #태그2` 형태면 태그 pill로 표시 (나무위키에는 없는 결타래 자체 기능).

**의도적으로 제외한 문법**: `#redirect` — 실제 위키 서버의 문서 이동/리다이렉트 기능이라 로컬 단일
파일 구조와 안 맞음(대신 검색 전용 별칭이 필요하면 위 `[[별칭:이름]]` 참고). `[math(...)]`, `[youtube(...)]`, `[ruby(...)]`, `[age(...)]`, `[dday(...)]`
매크로 — 필요하면 개별로 추가 가능.

## 글양식 (새 문서 기본 양식)

틀과는 별개 개념. "+ 새 문서"로 문서를 만들 때 기존 틀 문서 중 하나를 골라 그 내용을 **한 번만 복사**해서
시작할 수 있음(매개변수는 기본값으로 채워짐). `{{틀:이름}}` 호출처럼 계속 연결되어 있는 게 아니라 그
순간의 내용을 그대로 가져오는 것이라, 이후 자유롭게 고쳐 써도 원본 틀에는 영향이 없음. 실제
MediaWiki 계열 위키에서 템플릿 문서를 `{{subst:틀}}`로 한 번만 복사해 쓰는 것과 같은 방식으로, 별도
저장 공간 없이 기존 틀 문서를 재사용함.

## 편집 화면 (탭 · 찾기)

- **탭**: 사이드바/위키링크/`[편집]` 등 어떤 경로로 문서를 열어도 브라우저 탭처럼 위쪽에
  쌓임 — 같은 문서를 다시 열면 새 탭 대신 기존 탭으로 전환됨. 탭을 벗어나기 직전 그 탭에
  아직 디스크에 안 써진 변경이 있으면 즉시 저장해 두고 넘어가므로 빠르게 전환해도 내용이
  사라지지 않음. ×로 개별 탭 닫기(재시작하면 초기화됨 — 워크스페이스처럼 영속하진 않음)
- **찾기(Ctrl+F) / 찾아 바꾸기(Ctrl+Shift+F)**: 지금 열린 문서 안에서만 찾음(사이드바의
  "제목·내용 검색"은 워크스페이스 전체를 뒤지는 전역 검색이라 별개). 다음/이전은
  Enter/Shift+Enter로도 가능
- **Shift+더블클릭**: 뷰어(왼쪽 렌더링 결과)에서 단어를 Shift+더블클릭하면 에디터의 그
  위치로 커서가 이동 — 가장 가까운 앞쪽 제목부터 그 단어를 원문에서 찾아가는 방식이라
  완벽하진 않음(같은 구간에 같은 단어가 여러 번 있으면 첫 번째로 감)

## 상용구 · 고유명사 사전 (편집 보조 기능)

문서 문법이 아니라 편집을 도와주는 기능 두 가지 (Galpi 프로젝트의 같은 이름 기능을 이식):

- **상용구**: 사이드바 "상용구"의 ⚙ 버튼으로 관리 모달을 엶(Galpi의 "상용구 관리" 화면과 같은 구성) —
  폴더 선택(+ 새 폴더), 단축어·본문을 한 화면에서 같이 입력하는 등록 폼, "일괄" 버튼으로 여러 줄
  한꺼번에 등록(`단축어::::본문` 또는 `단축어(본문)` — 후자는 괄호 안팎 중 한글이 아닌 쪽을 자동으로
  단축어로 인식), 검색, 목록(수정·삭제·"에디터에서 열기"로 표처럼 긴 본문을 툴바 도움받아 계속
  작성)까지 모달 하나에서 처리. 문서 편집 중 등록해 둔 단축어의 뒷부분을 타이핑하면 커서 근처에
  후보 팝업이 뜨고 방향키+Tab/Enter로 확정("타이핑 중 추천 팝업" 체크박스로 끌 수 있음), 단축어를
  끝까지 정확히 치고 스페이스를 누르면 팝업 없이 바로 치환("스페이스바 자동 치환" 체크박스로 별도
  on/off — 동일 길이 동음이의 단축어가 카테고리 다르게 여럿이면 숫자 선택 팝업이 뜸). Alt+Enter를
  누르면 이 설정과 무관하게 항상 수동으로 같은 치환을 발동(일치하는 게 없으면 그냥 평소
  Alt+Enter처럼 줄바꿈만 들어감). 본문 안에
  `{#}`를 넣어두면 치환 후 커서가 그 자리로 이동(마커 자체는 삽입되지 않음). 툴바의 "상용구 삽입"
  버튼은 두 체크박스와 무관하게 항상 동작 — 필터 없이 전체 목록에서 고를 수 있고 앞 9개는 숫자키
  1~9로도 선택 가능. 데이터는 자료 공간과 같은 구조로 저장됨(`.wikidesk-snippets/{카테고리}/{제목}.md`,
  파일 내용이 곧 본문)
- **고유명사 사전**: 사이드바 "사전 관리"로 모달을 엶 — `원문`/`한자/영문`을 입력해 등록, "일괄"로
  `원문(한자)` 줄을 여러 개 한 번에 등록, 검색(Enter로 실행 — 항목이 10만 개를 넘어갈 수 있어서
  Galpi처럼 검색 전에는 목록을 그리지 않음), 결과에서 수정·삭제. 사전은 메인 에디터로 열어서
  편집하지 않음 — 항목이 아주 많아지면 문서 전체를 매 입력마다 다시 렌더링/파싱하느라 앱이 멎는
  수준으로 느려지기 때문(원문이 아주 많이 쌓인 워크스페이스에서 실제로 겪은 문제). 문서 편집 중
  등록된 원문 바로 뒤에서 **Alt+H**를 누르면 `원문` → `원문(한자1)` → `원문(한자2)` → ... → 다시
  `원문`으로 순환 치환됨

## 구조

- `electron/` — 메인 프로세스: 파일 읽기/쓰기, 워크스페이스 스캔, 실시간 감시(chokidar), 메타데이터 인덱스.
  분류(`.wikidesk-categories`)·자료(`.wikidesk-data`)·틀(`.wikidesk-templates`)·이미지(`.wikidesk-images`)·
  상용구(`.wikidesk-snippets`)·사전(`.wikidesk-dict`) 전용 공간도 여기서 스캔/생성함
- `src/lib/wikiParser.js` — 커스텀 위키 문법 파서 (틀 매개변수 치환용 `expandTemplates`도 여기에 있음)
- `src/lib/dictCycle.js` — 고유명사 사전 Alt+H 순환치환 순수 함수(`parseDictText`, `resolveCycleReplacement`)
- `src/store/useAppStore.js` — 앱 상태 (zustand) — `categoryIndex`/`dataIndex`/`templateIndex`/
  `snippetIndex`/`dictMap`도 여기서 관리 — 열린 문서 탭은 `tabs`/`activeTabId`로 관리하고,
  화면에 보이는 `openPath`/`rawText`/... 필드는 항상 활성 탭의 내용을 그대로 반영함(탭 전환
  시 `showInTab`/`switchTab`이 동기화)
- `src/components/` — 사이드바 트리(워크스페이스/분류/자료/틀/이미지/상용구), 탭 바(`TabBar.jsx`),
  헤더(뷰어/듀얼/집중 모드), 에디터(찾기/바꾸기는 `FindReplaceBar.jsx`), 뷰어

## 현재 범위 / 다음 단계

1차 버전은 문서 트리, 뷰어·듀얼·집중 모드, 표·각주·태그 렌더링, 로컬 자동저장, 제목·내용 검색,
위키링크(`[[문서명]]`)까지 포함합니다. 역링크(이 문서를 링크한 문서 목록)는 2차로 예정되어 있습니다.

검색·분류/자료/틀/이미지 인덱스는 `useAppStore.js`의 `rebuildIndexes()`가 워크스페이스 전체를 스캔해서
메모리에 매번 다시 만드는 방식입니다(디스크에 별도로 저장해두지 않음). 예전에 `userData/index.json`에
따로 저장하는 `electron/metadataIndex.js`가 있었는데, 실제로 어디서도 읽어가는 곳이 없어서(저장만 하고
아무도 안 씀) 제거했습니다 — 검색용 영속 인덱스가 실제로 필요해지면(워크스페이스가 아주 커져서 매번
전체 스캔이 느려지는 시점 등) 그때 다시 설계하는 게 나을 것 같습니다.

# 문제 해결 기록: 문법 변환·뷰어 표시

본문 문법이 화면에 그려지는 방식(변환기·표·코드·각주·목차)에서 생긴 문제. 증상 → 원인 → 해결 순서로 남긴다. 전체 목차는 [`../troubleshooting.md`](../troubleshooting.md).

## 본문 문법이 엉뚱하게 변환됨: 코드·곱셈의 `*`, 목차 기호, `[[A&B]]`, 각주 안 `[[링크]]` 등 (2026-11-19)

**증상**: SQL·C 글의 `a*b*c`, `SELECT *`, `''` 가 기울임이 되거나 사라지고, 제목의 꾸밈 표시가 목차에 글자로 보이고, `[[A&B]]` 링크가 깨지고, 각주 안에 `[[링크]]`·`[0]` 이 있으면 각주가 중간에서 끝나 뒤가 새어 나왔다. 표 칸의 `<colcolor=...>` 는 글자로 남고, 다크 모드에서 노란 배경 칸의 글자는 거의 안 보였다.

**원인**: 변환기가 `*`·`''` 를 앞뒤 문맥 없이 꾸밈으로 봤고, 각주 끝을 "첫 `]`" 로 잡았고, 링크 이름의 `&` 를 이스케이프된 채 비교했고, 표 칸 표시의 종류를 정해 두지 않아 모르는 `<...>` 를 모두 같은 방식으로 처리했다. 배경색만 있는 칸은 테마의 글자색을 그대로 써서 밝은 배경과 겹쳤다. 코드를 자리 표시 글자로 빼는 과정에서는, 백틱 코드 안에 `{{{ }}}` 코드가 들어 있으면 안쪽 자리 표시(`@@WDCODE0@@`)가 되돌려지지 않고 화면에 새는 문제가 새로 생겼다(퍼즈 검사로 발견).

**해결**: 글자/숫자에 붙은 경우만 꾸밈으로 보게 했고, 각주 모양을 `lib/footnoteSyntax.js` 한 곳에 모아 뷰어·편집기가 같이 쓰게 했고, 아는 표 칸 표시만 읽고 나머지는 글자로 두었고(색 표시 `color/rowcolor/colcolor` 는 지원 추가), 배경색만 있는 칸에는 명암 대비로 글자색을 정했고, 인라인 코드를 저장할 때 안쪽 자리 표시를 원문으로 되돌리게 했다. 재현 테스트는 `tests/lib/wikiSyntaxReview.test.js`(고치기 전 40개 실패 -> 통과, 변이 검사 확인).

**교훈**: 변환기를 고친 뒤에는 시험 문장만이 아니라 **실제 문서 전체를 고치기 전후로 변환해 비교**하면 의도하지 않은 변화(이번에는 `<colcolor=>` 회귀)를 찾을 수 있다. 글을 자리 표시로 바꿔 두는 방식은 **자리 표시가 겹칠 때(코드 안의 코드)** 를 퍼즈로 확인한다.

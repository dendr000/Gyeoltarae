# 표 편집기의 계산·엑셀식 편의 기능 — 계획

- 작성일: 2026-10-13
- **진행 상황 (2026-10-13)**: 1단계(상태 표시줄 집계)를 **0.92.0 에서 구현 완료** — 문서: [table-editor-stats.md](../features/table-editor-stats.md). 이어서 "그 밖의 후보" 중 **행·열 중간 삽입**을 **0.93.0 에서 구현 완료** — 문서: [table-editor-insert.md](../features/table-editor-insert.md). **정렬**도 **0.94.0 에서 구현 완료** — 문서: [table-editor-sort.md](../features/table-editor-sort.md). **아래로·오른쪽으로 채우기**(표 편집기), **행·열 이동·복제**, **표 안 찾아 바꾸기**는 **0.95.0 에서 구현 완료** — 문서: [table-editor-structure.md](../features/table-editor-structure.md), [table-editor-find.md](../features/table-editor-find.md). 같은 버전에서 **줄 복제(Ctrl+D)를 문서 전체로 확장**했다([code-line-duplicate.md](../features/code-line-duplicate.md)). 2단계 이후는 쓰다가 필요해지면 별도 요청으로 진행한다.
- 관련 문서: [table-editor-keys.md](../features/table-editor-keys.md) (셀 키 이동), 나무위키 문법 기준은 README 의 표 문법 절.

## 요청과 결정

- 요청: 표 편집기에서 한 행·한 열의 숫자 합계, 곱셈, 뺄셈 등 엑셀식 편의 기능. 쓰임새는 "간단한 연산, 평균 구하기, 간단한 수학" 정도.
- **보기용이면 충분**하다고 정했다 → 계산 결과를 문서에 쓰지 않는 상태 표시줄부터 한다.
- **나무위키가 표본**이라 되도록 나무위키 문법 안에서 한다 → 문서에 새 문법을 끼워 넣는 일은 신중히(아래 3단계).
- 나머지는 권장안에 따른다.

## 계산 결과를 어디에 두나 — 세 가지 방식

| 방식 | 동작 | 장점 | 단점 |
|---|---|---|---|
| **A. 값 넣기** | 범위를 고르고 버튼을 누르면 옆·아래 빈 칸에 숫자가 **글자로** 들어감 | 문서 문법이 그대로라 나무위키 호환. 만들기 쉬움 | 원본이 바뀌어도 결과가 안 바뀜 |
| **B. 편집기 안 수식** | 셀에 수식을 저장하고 편집기에서만 계산해 보여 줌 | 편집 중에는 갱신됨 | 저장 형식이 필요하고 뷰어에는 반영되지 않음 |
| **C. 뷰어까지 수식** | 문서에 수식을 저장하고 뷰어가 계산해서 그림 | 진짜 엑셀처럼 동작 | 파서·표 렌더링 변경, 새 문법 필요 |

### 뷰어 "새로고침 버튼" 아이디어에 대한 검토 (2026-10-13 질문)

- 수식이 문서에 **저장돼 있으면(C)** 뷰어가 그릴 때마다 계산하므로 원본을 고치는 순간 저절로 갱신된다. 새로고침 버튼은 필요 없다.
- 버튼이 필요한 것은 "값을 글자로 넣어 두었다가(A) 버튼으로 다시 계산해 덮어쓰는" 경우다. 이때는 어느 칸이 어느 범위의 합계인지를 문서에 기억시켜야 해서, 결국 수식을 저장하는 것과 같아진다. 또 뷰어 버튼이 **문서 글을 직접 고치는 것**은 낯선 동작이라 권하지 않는다.
- 결론: 갱신이 필요해지면 **C 방식**으로 간다. 버튼 방식은 채택하지 않는다.

### 3단계(C)를 한다면 지킬 것

- **나무위키 호환**: 나무위키에서 열어도 깨지지 않고 그냥 글자로 보이도록, 표 셀의 `=글자=`(헤더 문법)와 충돌하지 않는 **매크로 모양**을 쓴다. 예: `[calc(SUM(B2:B5))]`. 수식이 `=` 로 시작하면 헤더 문법과 충돌한다.
- 뷰어 계산 결과는 읽기 전용이고 편집기에서는 수식 글자가 그대로 보여야 한다.
- 순환 참조(자기 칸을 포함하는 범위), 병합 셀, 헤더 행 제외 규칙을 1단계의 규칙(`tableStats.js`)과 같게 쓴다.

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 상태 표시줄: 고른 범위의 합계·평균·개수·최소·최대, 행 번호·열 글자로 줄 선택, 값 누르면 복사 | **0.92.0 완료** |
| 2 | A 방식: "합계 행 추가"·"이 칸에 넣기" 버튼, 열 계산 채우기(B×C → D, 사칙연산) | 미정 |
| 3 | C 방식: `[calc(...)]` 수식을 문서에 저장하고 뷰어가 계산 | 미정. 1~2단계를 써 보고 판단 |

### 2단계 메모

- **열 계산 채우기**: 수식 입력 없이 "열 B × 열 C → 열 D" 를 고르는 방식. 한 행씩 계산해서 결과를 글자로 넣는다. 사칙연산 4개와 소수 자릿수 선택이 필요하다.
- **합계 행 추가**: 고른 열 맨 아래에 `합계` 행을 넣는다. 1단계의 `rangeStats` 를 그대로 쓴다.
- 숫자 읽기 규칙은 1단계와 같게 쓴다(`parseCellNumber`).

## 그 밖의 엑셀식 편의 기능 후보 (난이도 순 어림)

처음(2026-10-13)에는 행·열 **삭제와 끝에 추가**만 있고 중간 삽입이 없었다(코드로 확인). 중간 삽입은 0.93.0 에서 추가했다. 외부 표(엑셀)에서 붙여넣기는 이미 된다.

| 기능 | 설명 | 난이도 |
|---|---|---|
| 행·열 중간 삽입 | 고른 칸 위/아래/왼쪽/오른쪽에 끼워 넣기 | **0.93.0 완료** |
| 행·열 이동·복제 | 위아래·좌우로 옮기기, 복제 | **0.95.0 완료** (병합이 걸린 줄은 단추가 꺼짐) |
| 정렬 | 열 기준 오름/내림, 숫자순·가나다순 | **0.94.0 완료** (세로 병합이 걸린 행은 정렬 불가) |
| 아래로 복사(Ctrl+D)·오른쪽으로 복사 | 고른 범위를 위 칸·왼쪽 칸 내용으로 채우기 | **0.95.0 완료** (오른쪽은 Ctrl+R 이 앱 메뉴의 새로고침과 겹쳐 단추만) |
| 표 안 찾아 바꾸기 | 공백 정리, 특정 글자 일괄 교체 | **0.95.0 완료** |
| 줄무늬 행 | 번갈아 배경색 | 쉬움 |
| 행·열 전치 | 가로와 세로를 뒤집기 | 쉬움 (병합 셀은 풀고 해야 함) |
| 방향키 이동 | 화살표로 셀 이동 (table-editor-keys.md 의 "알려진 한계") | 쉬움 |
| 자동 채우기 | `1, 2` → `3, 4…`, 날짜·요일 | 보통 |
| 숫자 서식 | 천 단위 쉼표, 소수 자릿수, `%`, 통화 기호 | 보통 |
| 조건부 색 | "0보다 작으면 빨강" 같은 규칙을 일괄 적용 | 보통 |
| 열 너비 지정 | 파서가 `<width=…>` 를 읽지만 편집기에서 조절은 못 함 | 보통 |

권장 순서(요청자 확인 전): 상태 표시줄(완료) → 행·열 중간 삽입(완료) → 정렬(완료) → 아래로 복사(완료) → 행·열 이동·복제(완료) → 찾아 바꾸기(완료). 남은 것: 자동 채우기, 숫자 서식, 조건부 색, 열 너비 지정, 줄무늬 행, 전치, 방향키 이동.

## 알려진 한계와 확인할 것

- `3만`, `1.5억` 처럼 단위가 크기를 바꾸는 표기는 숫자 3, 1.5 로 읽는다(곱하지 않음).
- `3호선` 같은 단위 꼴도 숫자로 읽혀서, 의미가 다른 칸을 한 범위로 고르면 합계가 어긋날 수 있다. 개수를 보고 확인한다.
- 실제 Electron 앱 창에서 눈으로 확인하지 않았다(미리보기에서 측정, 클립보드는 가짜 함수로 값만 확인).

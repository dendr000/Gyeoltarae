## 요청과 배경

웹툰·소설 작품의 등장인물 문서(`D:\WikiDesk\웹툰\작품명\등장인물\01 파랑.md` 등)에 인물이 많아지면(파일당 25명 이상, 작품당 50명 이상) 제목 문단은 목차가 너무 길어지고, 불릿만 쓰면 찾기 어렵다. 인물이 많은 문서에서 이름·특기·소속·등장 회차로 빠르게 찾고 걸러 볼 수 있는 **보기 기능**이 필요하다.

한 줄 정의: 문서 본문에 이미 적힌 인물 블록(`= 이름 =` + `키:값` 줄 + 설명 + `NNN 제목 대사` 회차 줄)을 읽어서 **표로 모아 보여 주고 걸러 보는 화면**. 문서 원문은 바꾸지 않는다.

참고 형식(이 형식을 읽을 수 있어야 함):

```text
[[분류:작품]]
[[분류:작품/등장인물]]

[목차]

= 귀능 =
특기:복사
서장의 비서인 판다 혼혈. 완력 2위.
078 긁적긁적
106 통행금지 “잽싸게 꺼져주세요.”

= 오수 =
특기:마약
스푼을 지원하는 스폰서.
031 마약 치료 “공룡?! 공룡이 걸어다녀?”
```

## 목표와 비목표

목표
- 열린 문서의 인물 블록을 표로 보고, 이름·특기·소속·등장 회차로 걸러 보기·정렬.
- 표의 행을 누르면 그 인물 위치로 이동.
- 인물 1,000명 문서에서도 입력이 멈추지 않음.

비목표
- 문서 원문 형식 변경, 새 문법 도입 (기존 문서가 그대로 열려야 함).
- 표에서 값을 고쳐 원문에 되쓰기 (1차에서는 보기 전용).
- 외부 서비스·계정 연동.

## 현재 상태·조사 (코드를 읽어 확인 전, 추정 포함)

- 뷰어는 `wikiParser.js` 로 글을 HTML 로 그린다. 제목 목록은 이미 목차(`FloatingToc`)가 뽑는다 → 제목 줄 인식 규칙을 재사용할 수 있다(추정, 구현 때 확인).
- 문서 점검(`docCheck.js`)이 있어 "속성 없는 인물·중복 이름" 점검을 같은 방식으로 붙일 수 있다.
- 표 편집기(`TableEditorModal`)는 `||` 표를 고치는 도구라 이번 기능과 목적이 다르다(방식 B 를 고르면 확장 대상).

## 추가 제안 (요청서에 없던 것)

1. **인물 점검**: 문서 점검에 "속성 없는 인물", "같은 이름 중복", "회차 줄 형식이 아닌 줄" 항목을 더한다(표 파싱 결과를 그대로 재사용).
2. **표를 문서로 내보내기**: 지금 거른 결과를 위키 표(`||`) 문법으로 복사해 다른 문서에 붙여 넣을 수 있게 한다(원문은 안 바뀜, 방식 B 의 장점을 선택적으로).
3. **값 칩 자동 집계**: 특기 같은 열의 값을 "복사 (3)" 처럼 개수와 함께 칩으로 보여 줘서 한 번 눌러 거른다.
4. **필터 기억**: 문서별로 마지막 필터·정렬을 기억(이 PC 의 설정 파일, 문서에는 안 씀).
5. **회차 그래프(후순위)**: 인물 한 명의 등장 회차를 가로 띠로 보여 줘 어디서 많이 나오는지 한눈에.
6. **인물 이름 링크**: 다른 문서에서 `[[귀능]]` 처럼 이름으로 링크하면 이 표/인물 위치로 이동(후순위, 기존 링크 규칙과 충돌 검토 필요).

## 파싱 규칙 초안 (구현 전 확정 필요)

- 인물 블록 = 제목 줄 하나(`= 이름 =` 같은 `=` 제목) ~ 다음 같은 레벨 이하 제목 직전. `[[분류:...]]`·`[목차]` 같은 앞부분은 인물이 아님.
- 블록 안에서 `키:값` 모양 줄(키는 짧은 글, 콜론 하나) = 속성. 회차 줄 = 숫자 3자리 이상으로 시작하고 공백 뒤 제목이 오는 줄. 나머지 = 설명.
- 소속 = 인물 제목보다 위 레벨의 가장 가까운 제목(있으면).
- 경계 입력: 빈 문서, 속성 없는 인물, `???` 이름, 같은 이름 중복(행은 둘 다 보이고 중복 표시), 비정상 이름 줄(예: 둘째 `〈이름〉` 같은 꼴 — 확인 필요), 회차 번호가 뒤바뀐 줄, 수천 줄 문서.

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 키:값 모양 줄과 일반 문장이 헷갈림(`주의: 이건 설명`) | 키 길이 제한과 알려진 키 우선, 헷갈리면 설명으로 처리하고 점검에서 알림 |
| 회차 줄과 숫자로 시작하는 설명이 헷갈림 | 숫자 3자리+공백 규칙을 고정하고 테스트로 못 박음 |
| 1,000명 문서에서 느림 | 열 때만 파싱, 가상 스크롤, 결과 기억 |
| 폴더 전체 모으기가 느림(M5) | 이미 있는 색인을 재사용, 별도 단계로 분리 |

## [Unreleased]

### 수정 (Fixed)
- Java 상용구 묶음의 추천 순서에서 `i` 를 쳤을 때 `interface` 가 `int` 보다 위에 오던 것을 고쳤다(이제 `int`, `interface`, `import`, `if` 순). 이미 설치한 폴더는 `_순서.txt` 에서 `int` 줄을 `interface` 위로 옮기면 된다. 이 PC 의 `D:\WikiDesk` 는 옮겨 두었다

### 변경 (Changed)
- 다른 사람에게 줄 배포 빌드에서 불필요한 파일을 뺐다: 계획서·CHANGELOG(`docs`), 임시 메모, 이 PC 경로가 든 바로가기, 쓰지 않는 `node_modules` 6천여 개. 앱 내부 파일(`app.asar`)이 약 56MB 에서 약 5MB 로 줄었다(앱 동작 변화 없음)
- 배포 폴더의 exe 옆에 라이선스(`LICENSE-Gyeoltarae.txt`), 제3자 고지(`THIRD_PARTY_NOTICES.md`), D2Coding 글꼴 파일과 OFL 라이선스·설치 안내(`fonts` 폴더)를 함께 넣는다
- 빌드가 끝나면 `app.asar` 안에 필요한 파일이 다 있는지, 넣지 않기로 한 파일이 새어 들어가지 않았는지 스스로 점검하고, 어긋나면 빌드를 실패로 끝낸다. 환경 변수 `GYELTARAE_PACKAGE_OUT` 으로 임시 위치에 빌드해서 확인할 수 있다
- 자동 시험이 약 50초에서 약 17초로 빨라졌다(1,800개 파일을 실제 디스크에 반복 설치하던 시험을 일부 이름으로 줄임). 바뀐 파일 관련 시험만 돌리는 `npm run test:changed` 를 추가했다 (동작 변화 없음)
- 문제 해결 문서에 편집 모드의 제목 강조·줄 번호·강조 점이 실제 앱에서 정상 동작함을 확인한 내용을 추가했다 (동작 변화 없음)
- 표 편집기 계산 기능의 방식 비교와 단계 계획을 계획서(`docs/plans/table-editor-calculations.md`)로 정리했다
- 표 편집기 상태 표시줄의 집계를 불필요한 메모 없이 바로 계산하도록 정리해서 린트 경고 3개를 없앴다 (동작 변화 없음)
- 오래된 버전의 변경 내역(0.1.0 ~ 0.80.0)을 `docs/changelog/` 보관 폴더로 옮겼다. 항목 내용은 그대로이고 이 파일 맨 아래에 링크가 있다 (동작 변화 없음)

## [0.130.0] - 2026-10-20 10:30

### 추가 (Added)
- 언어 상용구의 함수 이름이 괄호까지 들어가고 커서가 괄호 안에 선다: C++ 에서 `printf` 를 고르면 `printf();`, `strlen` 은 `strlen()`, `static_cast` 는 `static_cast<>()`. - 함수 호출 항목(`printf` → `printf();`)은 스페이스바 자동 치환에서 빠진다. 주석이나 글 속에서 `sort `, `print ` 를 쓸 때 코드가 끼어들지 않는다. 추천 팝업(Tab)과 Alt+Enter 로 쓴다

## [0.123.0] - 2026-10-19 16:10

### 추가 (Added)
- C++·Java·HTML·Python·JavaScript·TypeScript·C·C#·Go·Kotlin·Rust·Swift·PHP·Ruby·Bash·CSS 16개 언어의 상용구 묶음을 추가했다. 언어마다 폴더 하나에 키워드·표준 라이브러리 이름(`namespace`, `ArrayList`, `enumerate` 등)과 `for` 반복문·`main` 함수·클래스 뼈대 같은 틀(`fori`, `psvm`, `ifmain`, `html5` 등) 6,262개가 들어 있다. 설치는 `node scripts/install-snippet-pack.mjs langs`(언어 하나만은 `cpp`, `java` 처럼 이름을 적는다)이고, 이미 있는 상용구는 덮어쓰지 않는다

### 변경 (Changed)
- **호환 깨짐** 폴더 이름이 언어 이름(`C++`, `Java`, `Python`, `SQL` 등)인 상용구 폴더는 이제 그 언어의 코드블록 안에서만 추천 팝업·스페이스바 치환·Alt+Enter 에 쓰인다. 글(문단)에서는 `SQL` 폴더의 `SELECT` 같은 키워드가 더 이상 뜨지 않는다. 글에서도 쓰고 싶은 상용구는 언어 이름이 아닌 폴더(`공통` 등)로 옮긴다. 폴더 이름이 언어 이름이 아니면 예전과 같다
- 코드블록 안에서 추천 후보의 순서가 그 블록 언어의 폴더 → 언어와 상관없는 폴더 순이 되었다
- 코드블록 색을 조정했다: HTML 의 속성 이름(`href`)과 CSS 의 속성(`color`)이 태그·선택자와 다른 색으로 보이고, `this`·`self` 는 키워드 색이다. 가상 클래스(`:hover`)는 선택자 색이다
- 상용구 사이드바에서 항목이 40개를 넘는 폴더는 처음에 접혀 있고, 폴더 이름 줄(개수 표시)을 눌러 펼친다. 상용구가 수천 개여도 사이드바가 느려지지 않는다
- 상용구 모달의 목록은 한 번에 300줄까지만 보여 주고 나머지는 폴더 선택·검색으로 좁히게 했다

- 같은 범위의 다른 문서에서 쓴 영어 단어(예: CREATE)를 추천 팝업에 "단어" 항목으로 보여 준다. 범위는 두 번째 단계 폴더(예: 강의/따즈아)이고, 상용구가 먼저 나온 뒤 많이 쓴 단어 순서로 나온다. 상용구 모달의 "폴더별 사용" 탭에서 켜고 끌 수 있다(기본 켜짐)
- 상용구 모달 "폴더별 사용" 탭에 최상위 폴더마다 "전체 문서에서 단어 모으기" 체크를 추가했다. 켜면 그 최상위 폴더 아래 모든 문서의 단어를 쓴다(기본 꺼짐)

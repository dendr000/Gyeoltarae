# 변경 내역

## [0.59.0] - 2026-09-18 10:24:13

### 변경 — 프로젝트명을 WikiDesk에서 결타래(Gyeoltarae)로 변경
- 사용자에게 보이는 곳(창 제목, 사이드바 상단, 처음 화면, README, package.json의
  productName/author) 전부 **결타래**로 바꿈. 저장소/폴더명처럼 로마자가 필요한 자리는
  Galpi 프로젝트와 같은 방식으로 **Gyeoltarae**를 씀
- **워크스페이스 안 실사용 데이터는 건드리지 않음** — `.wikidesk-categories`/
  `.wikidesk-data`/`.wikidesk-templates`/`.wikidesk-images`/`.wikidesk-snippets`/
  `.wikidesk-dict` 폴더명, `wikidesk-*` localStorage 키(테마 등)는 그대로 둠. 이미 이
  이름으로 만들어진 실제 워크스페이스(예: `D:\WikiDesk`)의 자료/틀/이미지/상용구/사전이
  이름 하나 안 맞아서 전부 안 보이게 되는 사고를 막기 위함
- **Electron 내부 앱 식별자도 `app.setName('wikidesk')`으로 명시적으로 고정** —
  `productName`이 바뀌면 Electron이 기본으로 쓰는 앱 이름(userData 저장 위치의 기준)도
  같이 바뀌는데, 그러면 `config.json`(마지막으로 연 워크스페이스 기억)이 있는 폴더 자체가
  바뀌어서 실행할 때마다 워크스페이스를 새로 선택해야 하는 상황이 됐을 것. 이 한 줄로
  브랜드가 바뀌어도 저장 위치는 그대로 유지됨
- `package.json`의 `"name"`(내부 npm 식별자)도 `gyeoltarae`로 바꿈 — 위 `app.setName()`
  안전장치 덕분에 이 필드를 바꿔도 실행 중 동작에는 영향 없음
- 실행파일/빌드 폴더명은 처음엔 한글("결타래-win32-x64", "결타래.exe")로 시도했다가 실제
  버그를 만났음: `@electron/packager`가 한글 이름을 내부적으로 NFD(자모 분해) 형태로
  정규화해서, 겉보기엔 똑같은 "결타래"인데 이 프로젝트의 다른 스크립트가 참조하는 NFC
  형태와 바이트가 달라 파일을 못 찾는 문제가 있었음(`Test-Path`가 실패). 그래서 경로로
  쓰이는 실행파일·빌드 폴더명은 로마자 `Gyeoltarae`로 고정하고, 직접 만드는 바로가기
  파일(`결타래.lnk`, 사용자가 탐색기에서 보는 이름)만 한글을 유지함
- 프로젝트 루트의 옛 `WikiDesk.lnk`·`release-packager\WikiDesk-win32-x64\`는 정리함.
  워크스페이스 폴더(예: `D:\WikiDesk`) 안에 이미 있던 `WikiDesk.lnk`는 그대로 남아있음
  (여전히 정상 동작함 — 지우고 싶으면 직접 지우면 새 실행 시 `결타래.lnk`가 자동 생성됨)
- `docs/CHANGELOG.md`·`docs/plans/*.md`·`docs/code-review.md`의 과거 기록은 일부러
  손대지 않음 — 그 시점엔 실제로 WikiDesk였다는 역사적 사실이라 바꾸면 오히려 부정확해짐
- `package-lock.json`은 다음에 `npm install`을 실행하면 저절로 이름이 맞춰짐(지금은 손대지
  않음 — 락파일을 손으로 고치는 건 위험해서 npm 자체 동작에 맡김)

## [0.58.0] - 2026-09-18 02:29:45

### 추가
- **탭**: 여러 문서를 동시에 열어 두고 브라우저처럼 전환. 사이드바/위키링크/`[편집]` 등
  어떤 경로로 열어도 같은 문서면 새 탭 대신 기존 탭으로 전환됨. 탭을 벗어나기 직전 그
  탭에 아직 디스크에 안 써진 변경이 있으면 그 자리에서 즉시 저장해 두고 넘어감(디바운스
  타이머가 아직 안 돌았어도 전환 도중 내용이 사라지지 않음). × 로 개별 탭 닫기, 마지막
  탭을 닫으면 빈 화면으로 돌아감. 재시작하면 초기화됨(워크스페이스처럼 영속하진 않음)
- **찾기 / 찾아 바꾸기** (현재 문서 안에서만 — 사이드바 검색은 워크스페이스 전체 대상이라
  별개): Ctrl+F 찾기, Ctrl+Shift+F 찾아 바꾸기. 다음/이전(Enter/Shift+Enter), 바꾸기,
  모두 바꾸기 지원
- **Shift+더블클릭으로 뷰어→에디터 이동**: 뷰어에서 단어를 Shift+더블클릭하면 에디터의
  해당 위치로 커서가 이동(가장 가까운 앞쪽 제목부터 그 단어를 원문에서 찾아가는 방식이라
  같은 구간에 같은 단어가 여러 번 있으면 첫 번째로 감 — 완벽하진 않지만 대부분 충분함)
- **상용구 Alt+Enter 수동 치환**: Galpi 원본에 있던 기능인데 처음 이식할 때 빠뜨림. 커서
  앞이 등록된 단축어와 정확히 일치하면 팝업 없이 즉시 치환(스페이스바 자동 치환 설정과
  무관하게 항상 동작 — 툴바 버튼과 같은 성격의 수동 트리거)
- **`[br]`**: 명시적 줄바꿈 매크로(실제 나무위키 문법). 문단이나 각주(`[* 내용]`) 안에서
  그냥 줄바꿈을 쳐서는 반영이 안 되던 것을 이걸로 강제할 수 있음
- **Ctrl+Shift+Alt+-**: 취소선 단축키 추가(굵게 Ctrl+B, 밑줄 Ctrl+U와 같은 자리)

### 수정
- **목록 항목 뒤에 오는 이어쓰기 줄이 무관한 새 문단으로 떨어져 나가던 문제 수정**. 실제
  나무위키는 `* 항목` 다음 줄에 별다른 문법 없이 그냥 텍스트가 와도(빈 줄로 끊기 전까지)
  그 항목이 계속되는 걸로 보는데, 지금까지는 그 줄이 목록과 완전히 분리된 별개 문단으로
  렌더링되고 있었음. 이제 항목 글자 밑으로 들여써져 보이고, 연속된 여러 줄도 전부 같은
  항목에 붙음
- **`[편집]`으로 이동했을 때 스크롤 위치가 부정확하던 문제 수정**. 커서 자체는 정확한
  자리로 갔지만, 스크롤 위치는 그 앞 문단들의 줄바꿈 개수만 세어 추정하고 있었음 — 문단이
  화면 폭보다 길어 자동으로 줄바꿈되는 경우(산문 위주 문서에서 흔함) 그 줄바꿈된 만큼을
  못 세서 스크롤이 실제 위치보다 한참 못 미치게 멈췄음. 자동완성 팝업 위치 계산에 이미
  쓰던 것과 같은 방식(보이지 않는 미러 요소에 커서 앞 텍스트를 그대로 채워 실제 줄바꿈을
  반영한 픽셀 위치를 재는 기법)으로 정확하게 계산하도록 고침

### 확인 필요
- **컨트롤 B가 안 먹는 문서가 있다는 제보**: 재현·원인 특정을 못 했음. 유력한 후보는
  듀얼 모드에서 "뷰어(왼쪽 렌더링 결과)" 쪽 텍스트를 선택한 채로 눌렀을 가능성 —
  Ctrl+B는 항상 "에디터(오른쪽 원문 textarea)"의 선택 영역에만 적용되는데, 듀얼 모드에서
  양쪽에 비슷한 텍스트가 나란히 있으면 어느 쪽을 선택했는지 헷갈리기 쉬움. 실제로 에디터
  쪽이 아니라 뷰어 쪽을 선택하고 있었는지 확인 부탁드림 — 맞다면 코드 문제가 아니라 이
  기능 자체의 태생적 한계라 안내 문구 등 다른 해결책이 필요함. 아니라면 재현 방법(어떤
  문서, 어떤 조작 순서)을 더 구체적으로 알려주시면 다시 조사하겠음
- Alt+H가 실제 Windows exe에서 메뉴 니모닉과 충돌 없이 동작하는지는 여전히 실기기 확인
  필요(이전부터 이어진 항목)
- 탭 닫기 단축키(Ctrl+W)는 일부러 안 넣었음 — Electron 기본 메뉴의 "닫기"가 이미 그
  단축키를 쓰고 있어서, 렌더러에서 가로채려다 오히려 창 전체가 닫힐 위험이 있다고 판단함.
  탭은 × 버튼으로만 닫음

- **`@매개변수@` / `@매개변수=기본값@` 틀 매개변수 치환** — 실제 나무위키 문법. 값을 아예 안 넘기면(호출에서 그 이름 자체가 없으면) 기본값이 나오고, 빈 문자열로 넘기면(`이름=,`) 빈 문자열이 나옴(기본값으로 안 넘어감 — 이 구분 덕분에 `@이름=b@속성:값;` 같은 조건부 CSS 선언 트릭도 그대로 동작함). 기존 `{{{매개변수}}}`/`{{{매개변수|기본값}}}` 문법도 하위 호환으로 계속 지원(실제 나무위키 문법인지는 불확실)
- **`{{{#!if 조건식}}}` 조건부 블록** — 대입(`=`, `;`로 여러 문장 연결 시 유지됨)·비교(`== != < <= > >=`)·논리(`&& || !`)·산술(`+ - * / %`)·단항(`! - +`)·삼항(`?:`)·소괄호·`this.매개변수`/`this['매개변수']`까지 지원하는 진짜 작은 표현식 엔진으로 구현(`src/lib/ifExpr.js`). 미지원: `**`(나무위키 특유의 좌→우 우선순위 포함), 증감연산(`++`/`--`), 비트연산, 문자열 메서드/속성(`.length` 등), `parseInt()`/`time()` 같은 전역 함수, 배열·객체, `<rowif>`, 복합 대입. 이런 문법이 쓰인 조건식은 그 블록만 평가 실패로 숨겨지고 문서 전체는 안 깨짐
- **`[include(틀:이름, ...)]`처럼 이름에 `틀:` 접두사가 붙어있어도 인식** — 실제 나무위키 문서를 그대로 복사해오면 이 접두사가 붙어있는 경우가 많은데, 지금까지는 이걸 그대로 이름의 일부로 취급해서 틀을 못 찾았음(역링크 집계도 마찬가지로 고침)
- 틀 호출 매개변수 값의 좌우 공백을 실제 나무위키처럼 제거(여러 줄로 나눠 쓴 `[include(...)]` 호출에서 값 앞에 줄바꿈이 섞여 들어가던 것 방지)

  - 유형+이름처럼 두 번 연달아 묻던 것도 이제 필드 두 개가 있는 모달 하나로 한 번에 입력하도록 개선(새 문서 만들 때 글양식 선택도 이름 입력과 한 모달에서 같이 처리)

- **접기 문법(`{{{#!folding ...}}}`)이 나무위키 실제 문법과 다르게 동작하던 버그 수정**: 나무위키 공식 문법 도움말(나무위키:문법 도움말) 기준으로, 닫는 `}}}`가 내용 줄 끝에 바로 붙어도(`__내용__}}}`처럼, 꼭 그 줄에 단독으로 있지 않아도) 되는데, 기존 파서는 `}}}`가 반드시 단독 줄에 있어야만 블록이 닫히는 걸로 잘못 인식했음. 그 결과 이렇게 쓴 접기 블록이 문서 끝까지 계속 이어진 것으로 처리되어 버렸음. 표 셀 안 `{{{#!wiki}}}` 블록 처리(`mergeMultilineTableRows`)에는 이미 있던 중첩 깊이 계산 방식을 본문 파서에도 동일하게 적용해서 해결 — `{{{+1 ...}}}` 같은 중첩된 삼중괄호 문법이 안에 있어도 안전하게 처리됨
- **분류 출력명(`[[분류:이름|출력명]]`) 미지원 수정**: 나무위키처럼 분류 배지에 보이는 글자를 실제 분류명과 다르게 지정할 수 있음 — 분류 자체(멤버십·상위/하위 분류)는 항상 실제 이름 기준으로 유지되고, 배지에 보이는 글자만 바뀜
- 위 두 가지 모두 나무위키 공식 문법 도움말 문서를 직접 확인하고 비교해서 발견·수정함

## [0.4.0] - 2026-09-14

### 추가
- **표 셀 그라데이션 배경**: 나무위키 실제 문법 확인 후 지원 — 표 셀 안에 `{{{#!wiki style="..."}}}` 블록이 여러 줄에 걸쳐 들어가는 실제 구조를 그대로 파싱(`mergeMultilineTableRows`). 이중 색상 `{{{#글자색,#배경색 텍스트}}}`, `[br]` 줄바꿈도 함께 지원. 툴바에 "그라데이션 표" 버튼으로 바로 예시 삽입 가능
- **표 편집기 엑셀식 범위 선택**: Shift+클릭으로 사각 범위 선택 → 배경색·글자색·정렬을 선택 범위 전체에 일괄 적용
- **표 편집기 복사/붙여넣기**: Ctrl+C/V(또는 툴바 버튼)로 셀 범위를 서식 포함 복사·붙여넣기. 대상이 기존 그리드보다 크면 행/열 자동 확장. 외부(엑셀 등)에서 복사한 탭 구분 텍스트 붙여넣기도 지원(이 경우 서식 없이 텍스트만)

### 알려진 제한
- 표 셀 그라데이션은 시각 편집기(그리드)에서는 만들 수 없고 툴바의 "그라데이션 표" 삽입 후 직접 수정해야 함 (그리드 UI는 셀 하나가 통짜 스타일 블록이 되는 구조를 표현하기 어려움)

## [0.3.0] - 2026-09-14

### 수정
- **실행취소(Ctrl+Z) 버그**: 툴바 버튼이 React 상태를 직접 덮어써서 텍스트 영역의 네이티브 되돌리기 기록이 끊기던 문제. `document.execCommand('insertText', ...)`로 바꿔 실제 타이핑과 동일하게 되돌리기 스택에 쌓이도록 수정
- **글자색 미적용 버그**: `{{{#색상 텍스트}}}` 인라인 글자색이 내부적으로 `#`이 중복 처리되어 조용히 무시되던 문제 (표 배경색은 정상이었음). `safeColor()`가 `#` 유무 두 형식을 모두 정규화하도록 수정

### 추가
- 서식 툴바 디자인 개선: 단순 버튼 나열 → 아이콘(lucide-react) + 그룹별 구분선으로 재구성 (구조/서식/삽입 3그룹)
- '집중' 모드 이름을 '편집'으로 변경, 뷰어/듀얼/편집 모드는 헤더 정중앙에 배치
- `{{{#!wiki style="..."}}}` 자유 스타일 블록 추가 — 그라데이션·그림자·테두리 등 나무위키 심화 문법 지원. 위험한 속성(`position`, `url()`, `@import` 등)은 허용 목록 방식으로 원천 차단
- 표 편집기에 셀별 배경색·글자색·정렬(왼쪽/가운데/오른쪽) 컨트롤 추가 (셀을 선택하고 위쪽 미니 툴바로 적용, HWP/스프레드시트 방식). 기존 표를 열어 편집할 때도 이 속성들이 보존되도록 파싱 로직 확장
- 사이드바에 `.md`/`.txt` 파일 드래그 앤 드롭으로 새 문서 불러오기 추가 (`.hwp`/`.docx` 등 바이너리 포맷은 미지원 — 별도 파서 필요)

### 알려진 제한
- 표 편집기는 여전히 셀 병합을 마우스로 드래그해서 하는 기능은 없음 (병합은 기존처럼 문법을 직접 입력해야 함)
- 표 셀 안의 그라데이션은 지원하지 않음 (나무위키 자체에서도 셀 내부 그라데이션의 정확한 문법이 불확실해 임의로 구현하지 않음)

## [0.2.0] - 2026-09-14

### 추가
- 나무위키 문법 대폭 확장: `=제목=`(1~6단계), `'''굵게'''`/`''기울임''`, `^^위첨자^^`, `,,아래첨자,,`, 글자 크기(`{{{+1}}}`~`{{{+5}}}`/`{{{-1}}}`~`{{{-5}}}`), 글자색(`{{{#색상 ...}}}`), 목록(중첩 `*`, `1.`), 인용(중첩 `>`), 표 셀 확장 속성(가로/세로 병합, 정렬, 배경색 — 다중 스택 지원), 코드블록·접기(`{{{ }}}`, `{{{#!folding}}}`), 자동 목차(`[목차]`), 구분선 굵기 4단계, `[[문서명]]` 표시(클릭 이동은 2차)
- 기존 `#` 제목, `**굵게**`, `*기울임*`, `--취소선--`, `||=헤더=||`는 WikiDesk 전용 확장으로 유지 (진짜 나무위키 문법과 구분해서 README에 표로 정리 — 나무위키에 그대로 옮길 문서라면 진짜 문법 쪽을 쓰는 걸 권장)
- 표 편집기 모달: 에디터 툴바의 "표 편집기" 버튼으로 행/열 추가·삭제, 셀 편집, 헤더 행 토글(진짜 나무위키 `'''굵게'''`로 저장) 후 삽입. 커서가 기존 표 안에 있으면 그 표를 파싱해 편집 모드로 열고 확인 시 제자리에서 교체
- `npm run dist:win:packager`(`@electron/packager`) 빌드 시 프로젝트 루트에 `WikiDesk.lnk` 바로가기 자동 생성/갱신

### 알려진 제한
- 표 편집기로 기존 표를 열어 수정하면 셀의 고급 속성(병합/정렬/배경색)은 유지되지 않고 일반 텍스트로 단순화됨 (헤더 행 굵게 표시만 유지)

## [0.1.0] - 2026-09-14

### 추가
- 프로젝트 초기 구성 (Electron + React + Vite)
- 나무위키 스타일 커스텀 문법 파서 (`#` 제목, `**굵게**`, `__밑줄__`, `~~취소선~~`, `*기울임*`, `[* 각주]`, `||표||`, `#태그`)
- 헤더 중앙에 뷰어 / 듀얼 / 집중 3단 모드 전환 (듀얼 모드: 좌측 뷰어 · 우측 에디터)
- 워크스페이스 폴더의 `.md` 파일 트리 사이드바, 문서/폴더 생성·이름변경·삭제(휴지통 이동)
- 파일시스템 실시간 감시(chokidar) → 외부 편집 시 트리 자동 갱신
- 편집 중 800ms 디바운스 자동저장, 저장 상태 표시(저장 중/저장됨/저장 실패)
- 시스템 / 라이트 / 다크 화면 모드 토글 (localStorage에 기억)
- Electron 기본 메뉴(파일/편집/보기/창) 한글화
- 태그·제목 메타데이터를 위한 JSON 기반 로컬 인덱스 (`electron/metadataIndex.js`) — 향후 SQLite 등으로 교체 가능하도록 분리
- Windows exe 빌드 스크립트 (`npm run dist:win`, electron-builder)

### 알려진 이슈
- `npm run dist:win` (electron-builder)은 이 PC 환경에서 `EPERM: rename win-unpacked.tmp` 오류가 재현됨. 관리자 권한, Defender 예외 등록, 제어된 폴더 액세스 해제로도 해결되지 않았고, 순수 Node.js `fs.rename`으로도 동일하게 재현되어 electron-builder만의 문제가 아님을 확인함(원인 미상 — 검색 인덱싱/OneDrive 백업 등 백그라운드 프로세스의 디렉터리 핸들 점유로 추정).
- **대안으로 `npm run dist:win:packager`(`@electron/packager` 기반, `scripts/package-win.js`)를 추가** — 이 방식은 파일을 개별 복사해 통째 rename을 하지 않아 위 문제를 피해가며, 정상적으로 `release-packager\WikiDesk-win32-x64\WikiDesk.exe`가 생성되고 실행도 확인됨. 다만 nsis 설치파일이 아닌 포터블 폴더 형태만 생성함(폴더째로 압축해 배포).

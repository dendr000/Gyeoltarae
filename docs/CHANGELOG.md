## [Unreleased]

### 수정 (Fixed)
- Java 상용구 묶음의 추천 순서에서 `i` 를 쳤을 때 `interface` 가 `int` 보다 위에 오던 것을 고쳤다(이제 `int`, `interface`, `import`, `if` 순). 이미 설치한 폴더는 `_순서.txt` 에서 `int` 줄을 `interface` 위로 옮기면 된다. 이 PC 의 `D:\WikiDesk` 는 옮겨 두었다

### 변경 (Changed)
- 다른 사람에게 줄 배포 빌드에서 불필요한 파일을 뺐다: 계획서·CHANGELOG(`docs`), 임시 메모, 이 PC 경로가 든 바로가기, 쓰지 않는 `node_modules` 6천여 개. 앱 내부 파일(`app.asar`)이 약 56MB 에서 약 5MB 로 줄었다(앱 동작 변화 없음)
- 배포 폴더의 exe 옆에 라이선스(`LICENSE-Gyeoltarae.txt`), 제3자 고지(`THIRD_PARTY_NOTICES.md`), D2Coding 글꼴 파일과 OFL 라이선스·설치 안내(`fonts` 폴더)를 함께 넣는다
- 빌드가 끝나면 `app.asar` 안에 필요한 파일이 다 있는지, 넣지 않기로 한 파일이 새어 들어가지 않았는지 스스로 점검하고, 어긋나면 빌드를 실패로 끝낸다. 환경 변수 `GYELTARAE_PACKAGE_OUT` 으로 임시 위치에 빌드해서 확인할 수 있다
- 자동 시험이 약 50초에서 약 17초로 빨라졌다(1,800개 파일을 실제 디스크에 반복 설치하던 시험을 일부 이름으로 줄임). 바뀐 파일 관련 시험만 돌리는 `npm run test:changed` 를 추가했다 (동작 변화 없음)
- 문제 해결 문서에 편집 모드의 제목 강조·줄 번호·강조 점이 실제 앱에서 정상 동작함을 확인한 내용을 추가했다 (동작 변화 없음)
- 표 편집기 계산 기능의 방식 비교와 단계 계획을 계획서(`docs/plans/table-editor-calculations.md`)로 정리했다
- 표 편집기 상태 표시줄의 집계를 불필요한 메모 없이 바로 계산하도록 정리해서 린트 경고 3개를 없앴다 (동작 변화 없음)

## [0.130.0] - 2026-10-20 10:30

### 추가 (Added)
- 언어 상용구의 함수 이름이 괄호까지 들어가고 커서가 괄호 안에 선다: C++ 에서 `printf` 를 고르면 `printf();`, `strlen` 은 `strlen()`, `static_cast` 는 `static_cast<>()`. C·Java·Python·JavaScript·TypeScript·C#·Go·Rust(`println!`, `vec!`)·Kotlin·Swift·PHP·CSS(`rgb`, `calc`)에도 적용했다. 문장으로 쓰는 함수에만 `;` 가 붙고 식 안에서 쓰는 함수에는 붙지 않는다. `size`·`count`·`min` 처럼 변수 이름으로도 흔한 단어는 그대로 단어로만 둔다
- 설치 스크립트에 `--refresh` 를 추가했다. 이미 설치한 폴더에서 처음 그대로인 단어(`printf`)만 새 본문(`printf({#});`)으로 바꾸고, 직접 고친 본문은 건드리지 않는다

### 변경 (Changed)
- 코드블록에서 이름 중간의 일치로는 스페이스바 자동 치환을 하지 않는다. `profori`, `my_free`, PHP 의 `$count` 처럼 식별자 끝이 틀 줄임말·단어와 같아도 바뀌지 않는다
- 함수 호출 항목(`printf` → `printf();`)은 스페이스바 자동 치환에서 빠진다. 주석이나 글 속에서 `sort `, `print ` 를 쓸 때 코드가 끼어들지 않는다. 추천 팝업(Tab)과 Alt+Enter 로 쓴다

## [0.123.0] - 2026-10-19 16:10

### 추가 (Added)
- C++·Java·HTML·Python·JavaScript·TypeScript·C·C#·Go·Kotlin·Rust·Swift·PHP·Ruby·Bash·CSS 16개 언어의 상용구 묶음을 추가했다. 언어마다 폴더 하나에 키워드·표준 라이브러리 이름(`namespace`, `ArrayList`, `enumerate` 등)과 `for` 반복문·`main` 함수·클래스 뼈대 같은 틀(`fori`, `psvm`, `ifmain`, `html5` 등) 6,262개가 들어 있다. 설치는 `node scripts/install-snippet-pack.mjs langs`(언어 하나만은 `cpp`, `java` 처럼 이름을 적는다)이고, 이미 있는 상용구는 덮어쓰지 않는다
- 코드블록 언어 이름 별명을 늘렸다: `C/C++`·`hpp`(C++), `xhtml`(HTML), `mjs`·`cjs`(JavaScript), `mts`(TypeScript), `pyw`(Python), `dotnet`(C#), `kts`(Kotlin), `shellscript`(Bash)

### 변경 (Changed)
- **호환 깨짐** 폴더 이름이 언어 이름(`C++`, `Java`, `Python`, `SQL` 등)인 상용구 폴더는 이제 그 언어의 코드블록 안에서만 추천 팝업·스페이스바 치환·Alt+Enter 에 쓰인다. 글(문단)에서는 `SQL` 폴더의 `SELECT` 같은 키워드가 더 이상 뜨지 않는다. 글에서도 쓰고 싶은 상용구는 언어 이름이 아닌 폴더(`공통` 등)로 옮긴다. 폴더 이름이 언어 이름이 아니면 예전과 같다
- 코드블록 안에서 추천 후보의 순서가 그 블록 언어의 폴더 → 언어와 상관없는 폴더 순이 되었다
- 코드블록 색을 조정했다: HTML 의 속성 이름(`href`)과 CSS 의 속성(`color`)이 태그·선택자와 다른 색으로 보이고, `this`·`self` 는 키워드 색이다. 가상 클래스(`:hover`)는 선택자 색이다
- 상용구 사이드바에서 항목이 40개를 넘는 폴더는 처음에 접혀 있고, 폴더 이름 줄(개수 표시)을 눌러 펼친다. 상용구가 수천 개여도 사이드바가 느려지지 않는다
- 상용구 모달의 목록은 한 번에 300줄까지만 보여 주고 나머지는 폴더 선택·검색으로 좁히게 했다

- 위 두 가지 모두 나무위키 공식 문법 도움말 문서를 직접 확인하고 비교해서 발견·수정함

- **그라데이션 편집기 모달** 신설 — "그라데이션"/"그라데이션 표" 버튼이 더 이상 정적 예시 텍스트만 꽂지 않고, 표 편집기와 같은 방식의 실시간 미리보기 모달을 엽니다: 방향(8방향 + 원형), 색상 2~4개, 내용, 굵기, (표 셀 모드는) 글자색·너비까지 눈으로 보면서 조정 후 삽입

### 수정
- 그라데이션 미리보기에서 `background`(단축)와 `backgroundClip`(개별 속성)을 함께 쓰던 것을 `backgroundImage`로 바꿔 React의 스타일 충돌 경고 제거

## [0.4.0] - 2026-09-14

### 추가
- **표 셀 그라데이션 배경**: 나무위키 실제 문법 확인 후 지원 — 표 셀 안에 `{{{#!wiki style="..."}}}` 블록이 여러 줄에 걸쳐 들어가는 실제 구조를 그대로 파싱(`mergeMultilineTableRows`). 이중 색상 `{{{#글자색,#배경색 텍스트}}}`, `[br]` 줄바꿈도 함께 지원. 툴바에 "그라데이션 표" 버튼으로 바로 예시 삽입 가능
- **표 편집기 엑셀식 범위 선택**: Shift+클릭으로 사각 범위 선택 → 배경색·글자색·정렬을 선택 범위 전체에 일괄 적용
- **표 편집기 복사/붙여넣기**: Ctrl+C/V(또는 툴바 버튼)로 셀 범위를 서식 포함 복사·붙여넣기. 대상이 기존 그리드보다 크면 행/열 자동 확장. 외부(엑셀 등)에서 복사한 탭 구분 텍스트 붙여넣기도 지원(이 경우 서식 없이 텍스트만)

### 알려진 제한
- 표 셀 그라데이션은 시각 편집기(그리드)에서는 만들 수 없고 툴바의 "그라데이션 표" 삽입 후 직접 수정해야 함 (그리드 UI는 셀 하나가 통짜 스타일 블록이 되는 구조를 표현하기 어려움)

## [0.3.0] - 2026-09-14

### 수정
- **실행취소(Ctrl+Z) 버그**: 툴바 버튼이 React 상태를 직접 덮어써서 텍스트 영역의 네이티브 되돌리기 기록이 끊기던 문제. `document.execCommand('insertText', ...)`로 바꿔 실제 타이핑과 동일하게 되돌리기 스택에 쌓이도록 수정
- **글자색 미적용 버그**: `{{{#색상 텍스트}}}` 인라인 글자색이 내부적으로 `#`이 중복 처리되어 조용히 무시되던 문제 (표 배경색은 정상이었음). `safeColor()`가 `#` 유무 두 형식을 모두 정규화하도록 수정

### 추가
- 서식 툴바 디자인 개선: 단순 버튼 나열 → 아이콘(lucide-react) + 그룹별 구분선으로 재구성 (구조/서식/삽입 3그룹)
- '집중' 모드 이름을 '편집'으로 변경, 뷰어/듀얼/편집 모드는 헤더 정중앙에 배치
- `{{{#!wiki style="..."}}}` 자유 스타일 블록 추가 — 그라데이션·그림자·테두리 등 나무위키 심화 문법 지원. 위험한 속성(`position`, `url()`, `@import` 등)은 허용 목록 방식으로 원천 차단
- 표 편집기에 셀별 배경색·글자색·정렬(왼쪽/가운데/오른쪽) 컨트롤 추가 (셀을 선택하고 위쪽 미니 툴바로 적용, HWP/스프레드시트 방식). 기존 표를 열어 편집할 때도 이 속성들이 보존되도록 파싱 로직 확장
- 사이드바에 `.md`/`.txt` 파일 드래그 앤 드롭으로 새 문서 불러오기 추가 (`.hwp`/`.docx` 등 바이너리 포맷은 미지원 — 별도 파서 필요)

### 알려진 제한
- 표 편집기는 여전히 셀 병합을 마우스로 드래그해서 하는 기능은 없음 (병합은 기존처럼 문법을 직접 입력해야 함)
- 표 셀 안의 그라데이션은 지원하지 않음 (나무위키 자체에서도 셀 내부 그라데이션의 정확한 문법이 불확실해 임의로 구현하지 않음)

## [0.2.0] - 2026-09-14

### 추가
- 나무위키 문법 대폭 확장: `=제목=`(1~6단계), `'''굵게'''`/`''기울임''`, `^^위첨자^^`, `,,아래첨자,,`, 글자 크기(`{{{+1}}}`~`{{{+5}}}`/`{{{-1}}}`~`{{{-5}}}`), 글자색(`{{{#색상 ...}}}`), 목록(중첩 `*`, `1.`), 인용(중첩 `>`), 표 셀 확장 속성(가로/세로 병합, 정렬, 배경색 — 다중 스택 지원), 코드블록·접기(`{{{ }}}`, `{{{#!folding}}}`), 자동 목차(`[목차]`), 구분선 굵기 4단계, `[[문서명]]` 표시(클릭 이동은 2차)
- 기존 `#` 제목, `**굵게**`, `*기울임*`, `--취소선--`, `||=헤더=||`는 WikiDesk 전용 확장으로 유지 (진짜 나무위키 문법과 구분해서 README에 표로 정리 — 나무위키에 그대로 옮길 문서라면 진짜 문법 쪽을 쓰는 걸 권장)
- 표 편집기 모달: 에디터 툴바의 "표 편집기" 버튼으로 행/열 추가·삭제, 셀 편집, 헤더 행 토글(진짜 나무위키 `'''굵게'''`로 저장) 후 삽입. 커서가 기존 표 안에 있으면 그 표를 파싱해 편집 모드로 열고 확인 시 제자리에서 교체
- `npm run dist:win:packager`(`@electron/packager`) 빌드 시 프로젝트 루트에 `WikiDesk.lnk` 바로가기 자동 생성/갱신

### 알려진 제한
- 표 편집기로 기존 표를 열어 수정하면 셀의 고급 속성(병합/정렬/배경색)은 유지되지 않고 일반 텍스트로 단순화됨 (헤더 행 굵게 표시만 유지)

## [0.1.0] - 2026-09-14

### 추가
- 프로젝트 초기 구성 (Electron + React + Vite)
- 나무위키 스타일 커스텀 문법 파서 (`#` 제목, `**굵게**`, `__밑줄__`, `~~취소선~~`, `*기울임*`, `[* 각주]`, `||표||`, `#태그`)
- 헤더 중앙에 뷰어 / 듀얼 / 집중 3단 모드 전환 (듀얼 모드: 좌측 뷰어 · 우측 에디터)
- 워크스페이스 폴더의 `.md` 파일 트리 사이드바, 문서/폴더 생성·이름변경·삭제(휴지통 이동)
- 파일시스템 실시간 감시(chokidar) → 외부 편집 시 트리 자동 갱신
- 편집 중 800ms 디바운스 자동저장, 저장 상태 표시(저장 중/저장됨/저장 실패)
- 시스템 / 라이트 / 다크 화면 모드 토글 (localStorage에 기억)
- Electron 기본 메뉴(파일/편집/보기/창) 한글화
- 태그·제목 메타데이터를 위한 JSON 기반 로컬 인덱스 (`electron/metadataIndex.js`) — 향후 SQLite 등으로 교체 가능하도록 분리
- Windows exe 빌드 스크립트 (`npm run dist:win`, electron-builder)

### 알려진 이슈
- `npm run dist:win` (electron-builder)은 이 PC 환경에서 `EPERM: rename win-unpacked.tmp` 오류가 재현됨. 관리자 권한, Defender 예외 등록, 제어된 폴더 액세스 해제로도 해결되지 않았고, 순수 Node.js `fs.rename`으로도 동일하게 재현되어 electron-builder만의 문제가 아님을 확인함(원인 미상 — 검색 인덱싱/OneDrive 백업 등 백그라운드 프로세스의 디렉터리 핸들 점유로 추정).
- **대안으로 `npm run dist:win:packager`(`@electron/packager` 기반, `scripts/package-win.js`)를 추가** — 이 방식은 파일을 개별 복사해 통째 rename을 하지 않아 위 문제를 피해가며, 정상적으로 `release-packager\WikiDesk-win32-x64\WikiDesk.exe`가 생성되고 실행도 확인됨. 다만 nsis 설치파일이 아닌 포터블 폴더 형태만 생성함(폴더째로 압축해 배포).

# 문법 전체 검수와 고친 점 (표·시간대·코드·목록·수식·각주·목차)

## 한 줄 요약

본문에 쓰는 위키 문법을 하나씩 까다롭게 살펴 **글이 엉뚱하게 변하거나 사라지던 문제 11가지**를 고쳤다. 실제 작업 폴더(문서 약 1만 개)의 변환 결과를 고치기 전후로 비교해, 달라진 문서 58개가 모두 좋아진 쪽인지 확인했다. 파일에 저장되는 글은 그대로이고 화면에 그려지는 방식만 달라진다.

## 고친 것

| 문법 | 예전 | 지금 |
|---|---|---|
| 제목 번호 | `= 큰제목 =` 없이 `=== 작은제목 ===` 만 쓰면 `0.1.` 처럼 보임 | 건너뛴 단계의 0 은 숨겨 `1.` 처럼 보임 |
| 목차 | 제목 속 꾸밈 표시(`''`, `[* 각주]`, `[[링크]]`)가 글자로 새거나 이동이 안 맞음 | 보이는 글자만 목차에 나오고 이동도 맞음 |
| 링크 `[[A&B]]` | `&` 가 들어간 문서 이름으로 가는 링크가 깨짐 | 정상 동작 |
| 표 칸의 `<...>` | 모르는 `<중요>` 같은 글이 지워지거나 표시로 오해됨 | 아는 표시만 읽고 나머지는 글자로 보임 |
| 표 칸의 `<^\|2>`, `<v\|2>` | 세로 병합 + 위/아래 맞춤을 못 읽음 | 읽음 |
| 표 칸의 글자색 `<color=>`, `<rowcolor=>`, `<colcolor=>` | 칸 앞에 글자로 남음 | 색이 적용됨(`colcolor` 는 그 칸부터 아래로 이어짐) |
| 표 칸의 배경색만 있는 칸 | 다크 모드에서 밝은 배경 + 밝은 글자라 안 보임 | 배경과 잘 구분되는 글자색을 자동으로 씀 |
| 글 속 코드 `{{{ }}}`, `` `백틱` `` | 안의 `*`, `__`, `''` 가 기울임·밑줄로 변함(SQL·C·파이썬 글이 깨짐) | 문법을 해석하지 않고 코드 모양으로 보임 |
| 곱셈·포인터·SQL 의 `*` 와 `''` | 두 별표 사이가 통째로 기울임이 됨 | 글자/숫자에 붙은 경우만 꾸밈으로 봄 |
| 번호 목록 `5. 다섯째` | 항상 1부터 다시 셈 | 쓴 번호부터 이어서 보임 |
| 수식 `$$ ... $$` | 서로 다른 문단의 `$$` 두 개가 사이 글 전체를 수식으로 묶음 | 빈 줄을 넘지 않음 |
| 각주 안의 `[[링크]]`, `[0]` | 첫 `]` 에서 각주가 끝나 뒤가 새어 나옴 | 짝이 맞는 대괄호는 각주 안에 그대로 있음(뷰어·편집기 같은 규칙) |

## 쓰는 법 (달라진 문법)

````text
코드 `__init__` 와 {{{SELECT * FROM t WHERE a*2 > b*3}}}
||<color=#2563eb> 파랑 글자 || 보통 ||
||<rowcolor=#dc2626> 이 줄은 빨강 || 둘째 칸도 빨강 ||
||<colcolor=#2563eb> 이 칸부터 아래로 파랑 || b ||
5. 다섯째부터
6. 여섯째
````

- 크기·색 표시 `{{{+2 글}}}`, `{{{#색 글}}}`, `{{{#!wiki ...}}}` 는 코드가 아니라 기존 문법 그대로다.
- 백틱은 여는 쪽 뒤와 닫는 쪽 앞이 공백이 아닐 때만 코드로 본다(`Ctrl+` 와 `Ctrl+Shift+``` 처럼 백틱이 두 개 있는 글을 코드로 오해하지 않으려고).
- 글자색을 직접 정한 칸이나, 배경이 색 이름(`yellow`)·`밝은색,어두운색` 쌍이면 자동 글자색을 쓰지 않는다.

## 구조

- `src/lib/wikiParser.js`: 변환 본체. 인라인 코드는 먼저 자리 표시 글자(`@@WDCODE번호@@`)로 빼 두었다가 맨 끝에 코드 모양으로 되돌려 다른 변환이 건드리지 못하게 한다. 각주 안의 코드는 원문으로 되돌려 각주를 따로 그릴 때 다시 처리한다.
- `src/lib/footnoteSyntax.js`: 각주 모양의 규칙 한 곳. 뷰어와 편집기(색칠·편집 상자)가 같이 쓴다.
- `src/lib/mathRender.js`: 수식 찾기(빈 줄을 넘지 않음).
- `src/components/FloatingToc.jsx`: 목차의 화면용 글(`label`)을 보인다. 이동에 쓰는 원문(`text`)은 따로 둔다.
- 시험: `tests/lib/wikiSyntaxReview.test.js`, `tests/lib/footnoteEdit.test.js`.

## 확인한 것

- 실제 작업 폴더 10,796개 문서를 고치기 전후로 변환해 비교(읽기만 함): 달라진 문서 58개를 모두 눈으로 봤고 의도한 개선뿐이다. 처음에 `<colcolor=>` 가 글자로 새는 회귀를 이 비교에서 찾아 고쳤다.
- 무작위 입력 14,000여 건: 예외 0건, 내부 자리 표시 글자가 화면에 새는 경우 0건.
- 실제 Electron 창(임시 폴더): 밝은 테마·어두운 테마에서 표(시간표·넓은 표)·코드·글자색 표·번호 목록·수식·각주 팝오버를 확인했다.

## 알려진 한계

- 표 칸의 `<color=>` 등은 `#색`, 색 이름, `밝은색,어두운색` 만 받는다(그 밖의 값은 글자로 남는다).
- 자동 글자색은 `#rgb`/`#rrggbb` 배경에만 계산한다.
- 편집기의 각주 색칠은 밝은 테마에서 눈으로 다시 확인하지 않았다(어두운 테마는 확인).

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| 파서(변환기) | 위키 글(`'''굵게'''` 같은 표시)을 화면에 보이는 모양(HTML)으로 바꾸는 부분 |
| 인라인 코드 | 문장 가운데 들어가는 짧은 코드. 글자 그대로 고정폭 글꼴로 보인다 |
| 자리 표시 글자 | 변환 도중 어떤 글을 잠깐 다른 눈에 띄지 않는 글자로 바꿔 두었다가 마지막에 되돌리는 방법. 중간 변환이 그 글을 건드리지 못하게 한다 |
| 회귀(regression) | 고치다가 전에 되던 것이 안 되게 되는 것 |
| 퍼즈(fuzz) 검사 | 일부러 엉뚱한 글을 무작위로 많이 넣어 보고 오류가 나는지 보는 시험 |
| 명암 대비 | 글자색과 배경색이 얼마나 잘 구분되는지. 낮으면 읽기 어렵다 |

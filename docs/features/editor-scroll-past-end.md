# 편집창 아래쪽 여백 (끝을 넘어 스크롤)

## 한 줄 요약

편집창에서 글 끝보다 더 아래로 스크롤할 수 있다. 끝까지 내리면 마지막 줄이 편집창 **맨 위 줄 자리**까지 올라와서, 글을 쓸 때 시선을 화면 아래가 아니라 위쪽에 둘 수 있다.

## 동작

- 글이 짧아도(예: 몇 줄뿐이어도) 아래로 스크롤할 수 있다. 끝까지 내리면 마지막 줄만 편집창 맨 위에 남고 나머지는 빈 화면이다.
- 여백의 크기는 **편집창 높이에 맞춰 자동으로** 정해진다(창 크기를 바꾸면 따라 바뀜).
- 마지막 줄은 완전히 사라지지 않고 맨 위 줄 자리에 남는다. (마지막 줄을 완전히 숨기면 커서가 어디 있는지 안 보여서 이 위치로 정했다)
- 스크롤 위치 기억, 제목 강조 막대, [편집] 점프 등 기존 동작은 그대로다.

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| **패딩(padding)** | 상자 안쪽의 여백. 글 아래에 빈 공간을 만들어서 더 스크롤할 수 있게 한다. |
| **컨테이너 쿼리 단위(`cqh`)** | 가장 가까운 "컨테이너" 높이의 1%. 여기서는 편집 칸 높이를 기준으로 여백을 계산하는 데 쓴다. |
| **배경판** | 제목 줄 강조를 위해 실제 글 뒤에 같은 글자를 투명하게 겹쳐 그리는 요소. 실제 글(textarea)과 여백이 같아야 스크롤이 어긋나지 않는다. |

## 구현 방식

- `src/App.css` 의 `.editor-text-wrap` 에 `container-type: size` 를 주고, `--editor-tail: calc(100cqh - 24px - 1px)` 를 정의한다. 실제 글 영역(`.editor-textarea`)과 배경판(`.editor-highlight-backdrop`)이 둘 다 이 값을 아래 여백(padding-bottom)으로 쓴다.
- **왜 칸 높이 전체가 아니라 `- 24px - 1px` 인가**: textarea 는 위·아래 여백의 합보다 작아질 수 없다. 아래 여백을 칸 높이 전체로 주면 위쪽 여백(24px)까지 합쳐 칸보다 24px 커져서 textarea 가 칸 아래로 삐져나왔다. 위 여백만큼 빼서 칸과 정확히 같은 높이가 되게 했다.
- 별도 자바스크립트(크기 감시 등) 없이 CSS 만으로 한다.

## 알려진 한계

- 마지막 줄을 완전히 가려지게 하는 것(여백을 더 크게)은 하지 않았다. 필요하면 `--editor-tail` 계산식만 바꾸면 된다(단, 위 "왜" 의 이유로 칸 높이를 넘기면 textarea 가 칸보다 커진다).
- 뷰어(오른쪽 렌더링 화면)에는 적용하지 않았다. 편집창만 해당한다.

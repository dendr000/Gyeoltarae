# 편집기 줄 단위 키 — Alt+←/→, 여러 줄 Tab, 목록·번호 목록·인용 이어쓰기

## 한 줄 요약

편집 모드에서 **줄 처음/끝으로 가는 Alt+←/→**, **여러 줄을 한꺼번에 들여쓰는 Tab / Shift+Tab**, **`* ` 목록 줄에서 Enter 를 치면 다음 항목을 자동으로 만들어 주는 기능** 세 가지가 추가되었다. 모두 문서 어디에서나 동작한다(Tab·Alt+방향키는 코드블록 안에서도 동작. Enter 이어쓰기는 코드블록 안에서 **들여쓰기만** 이어지고 목록·번호·인용 표시는 이어지지 않는다).

## 1. Alt+←/→ — 줄 처음/끝으로 이동

Home / End 키가 없는 노트북을 위해 만들었다.

| 키 | 동작 |
|---|---|
| Alt+← | 현재 줄의 맨 앞으로 |
| Alt+→ | 현재 줄의 맨 끝으로 |
| Alt+Shift+← | 커서에서 줄 맨 앞까지 선택 |
| Alt+Shift+→ | 커서에서 줄 맨 끝까지 선택 |

- **글 한 줄 기준**이다. 긴 줄이 화면에서 여러 줄로 접혀 보여도(줄바꿈 표시) 접힌 한 줄씩이 아니라 글의 줄 전체의 처음/끝으로 간다.
- 줄 맨 앞에서 Alt+←를 다시 눌러도 앞 줄로 넘어가지 않는다(끝도 마찬가지).
- 이미 선택이 있을 때 Shift 없이 누르면 선택이 풀리고 움직이는 쪽 끝에서 줄 처음/끝으로 간다.
- 이 키는 브라우저의 "뒤로 가기"와 같은 키이므로 편집기에서는 항상 기본 동작을 막는다.
- 숫자패드 `-` / `+` 를 Home / End 로 쓰는 기능은 넣지 않았다(노트북에는 그 키가 없고, NumLock 상태에서 숫자패드로 `-` `+` 를 입력하는 용도를 뺏지 않으려고).

## 2. Tab / Shift+Tab — 여러 줄 들여쓰기

**여러 줄을 선택한 채 Tab** 을 누르면 선택에 걸친 모든 줄 앞에 공백 4칸이 붙는다. **Shift+Tab** 은 그 줄들 앞의 공백을 최대 4칸(또는 탭 문자 1개)씩 지운다. VS Code 와 같은 방식이다.

````text
선택한 줄들            Tab ->            Shift+Tab ->
aa                      aa                aa
[bb                         bb            bb
cc]                         cc            cc
````

- **선택이 한 줄 안이거나 없으면** 예전처럼 커서 자리에 공백 4칸이 들어간다. (예전에는 선택한 글이 4칸 공백으로 바뀌어 사라졌는데, 여러 줄을 선택한 경우에는 이제 그렇지 않다. 한 줄 안의 선택은 이전과 같이 공백으로 바뀐다.)
- **Shift+Tab 은 선택이 없어도** 현재 줄 앞의 공백을 지운다. 지울 공백이 없어도 입력칸 밖으로 포커스가 나가지 않는다.
- **빈 줄은 들여쓰지 않는다**(보이지 않는 공백이 쌓이지 않게).
- **선택의 마지막이 다음 줄의 맨 앞**이면(줄 전체를 선택한 흔한 경우) 그 다음 줄은 건드리지 않는다.
- 들여쓴 뒤에도 같은 글자가 선택된 상태로 남아서, 이어서 Tab / Shift+Tab 을 누를 수 있다.
- **Ctrl+Z 한 번**으로 한 번의 들여쓰기가 전부 취소된다.
- 상용구/파일 추천 팝업이 열려 있으면 Tab 은 후보 확정이 먼저다(기존 규칙 그대로).

## 3. 목록·번호 목록·인용 이어쓰기 — 줄 끝에서 Enter

네 종류를 같은 규칙으로 다룬다(0.100.0 부터 번호 목록과 인용도, 0.107.0 부터 표시 없는 들여쓴 줄도 된다).

| 종류 | 예 | 줄 끝에서 Enter 하면 |
|---|---|---|
| 별표 목록 | `* 사과` | 아래 줄에 `* ` (깊이·들여쓰기 유지) |
| **번호 목록** | `1. 사과` | 아래 줄에 **다음 번호** `2. ` (`9.` → `10.`, 앞의 0 자릿수 유지: `01.` → `02.`, 들여쓰기 유지) |
| **인용** | `> 내용` | 아래 줄에 `> ` (`>>` 같은 깊이와 들여쓰기 유지, `>내용` 처럼 공백 없는 인용도 다음 줄은 `> `) |
| **들여쓴 줄** | `    내용` (표시 없이 공백·탭으로만 들여씀) | 아래 줄에 **같은 들여쓰기**(공백이면 공백, 탭이면 탭 그대로) |

**들여쓴 줄 이어쓰기**는 `* 항목` 처럼 표시가 있는 줄이 아니라 들여쓰기만으로 계층을 쓰는 글(묶음 정렬 Ctrl+Shift+` 로 정렬할 글 등)을 쓰기 편하게 하려는 것이다. 들여쓴 줄에 내용을 쓰고 Enter → 아래 줄이 같은 들여쓰기로 시작하고, **들여쓰기만 있는 줄에서 Enter → 그 들여쓰기가 지워져 빈 줄**이 된다(한 번 더 Enter 하면 새 줄). 들여쓴 `* 항목`·`1. 항목`·`> 인용` 은 위 표대로 표시를 이어받는다(들여쓰기만 이어받는 것이 아니다).

**코드블록(```) 안에서도 들여쓰기는 이어진다**(0.108.0 부터). 들여쓴 코드 줄 끝에서 Enter → 같은 들여쓰기로 새 줄, 들여쓰기만 있는 줄에서 Enter → 들여쓰기 삭제. 다만 **표시는 이어받지 않는다** — 코드 속의 `  * 주석`, `  1. 단계`, `  > 출력` 은 목록·인용이 아니므로 새 줄에는 들여쓰기만 생긴다. 들여쓰지 않은 코드 줄에서는 평소 Enter 다. (부작용: 공백만 있는 줄을 일부러 만들 수 없다. Enter 가 그 공백을 지운다.) 상용구·단어 추천 팝업이 떠 있을 때는 방향키로 후보를 고르기 전의 Enter 가 팝업만 닫고 줄바꿈 처리를 이어가므로 들여쓰기도 이어진다.

- `* 사과` 줄 **끝에서 Enter** → 아래 줄에 `* ` 가 자동으로 생긴다. 들여쓴 목록(`    * 배`)이나 별표가 여러 개인 목록(`** 깊은`)은 같은 들여쓰기·별표 개수를 이어받는다.
- 글 **중간에서 Enter** → 커서 뒤쪽 글이 새 항목(`* `, 다음 번호, `> ` 뒤)으로 내려간다.
- **내용이 없는 표시만 있는 줄**(`* `, `3. `, `> `, 들여쓰기만 있는 줄)에서 Enter → 그 표시(들여쓰기 포함)가 지워져 빈 줄이 된다. 목록·인용·들여쓰기 이어쓰기를 끝내는 방법이다.
- 동작하지 않는 경우(평소 Enter 그대로): 커서가 `* ` 표시보다 앞에 있을 때, 글을 선택한 상태일 때, Shift+Enter, 코드블록 안의 목록·번호·인용 표시(코드블록 안에서는 들여쓰기만 이어진다 — 아래), 한글 조합 중 Enter(글자 확정), 표시 뒤에 공백이 없는 목록 줄(`**굵게**`, `1.사과`), 영문 번호(`a.`)·로마 숫자(`I.`) 목록, 글 속에 들어 있는 `1.`·`>`(줄 맨 앞이 아닌 것, `->` 화살표). 커서가 `1.` 의 점 바로 뒤나 `>` 바로 뒤처럼 **표시 안**에 있어도 평소 Enter 다.
- Ctrl+Z 로 되돌릴 수 있다(빈 항목을 지운 것도 한 번에 되돌아온다).

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| 들여쓰기 | 줄 앞에 공백을 넣어 오른쪽으로 밀어 쓰는 것. 이 앱은 한 단계를 공백 4칸으로 센다 |
| 내어쓰기 | 들여쓰기의 반대. 줄 앞 공백을 지워 왼쪽으로 당기는 것 |
| 줄바꿈 표시(wrap) | 긴 줄이 화면 너비에서 다음 줄로 접혀 보이는 것. 글 자체에는 줄바꿈이 없다 |
| 선택 방향 | 선택을 앞→뒤로 만들었는지 뒤→앞으로 만들었는지. 기준점은 고정되고 반대쪽 끝이 움직인다 |
| 한글 조합 | 한글 자모를 모아 글자를 만드는 입력 중인 상태. 이때의 Enter 는 글자를 확정하는 키라서 가로채지 않는다 |

## 알려진 한계

- Alt+←/→ 는 글의 줄 기준이다. 화면에서 접힌 줄 기준(접힌 줄의 처음/끝)으로는 움직이지 않는다.
- 파서(`wikiParser.js`)의 들여쓰기 깊이 계산도 "탭 = 공백 4칸"으로 하드코딩되어 있다. 들여쓰기 단위를 바꾸려면 `indentUnit.js` 와 파서를 함께 봐야 한다.
- 번호 목록은 **이어쓴 줄만 번호를 매긴다.** 중간에 항목을 끼워도 뒤 번호를 다시 매기지 않는다(`1. 2. 3.` 사이에 끼우면 `1. 2. 3. 3.` 처럼 될 수 있음). 영문(`a.`)·로마 숫자 목록은 파서도 지원하지 않는다.
- 계획서: [`docs/plans/editor-input-improvements.md`](../plans/editor-input-improvements.md) 의 항목 1·3·4.

# 문서 점검 (메뉴 "편집" > "문서 점검")

## 한 줄 요약

지금 열린 문서에서 **화면이 엉뚱하게 보이게 만드는 흔한 실수**를 한 번에 모아 보여 주고, 항목을 누르면 편집기의 그 자리로 이동한다. 글은 고치지 않고 위치만 알려 준다.

## 찾아 주는 것

| 항목 | 뜻 | 종류 |
|---|---|---|
| 코드블록이 닫히지 않음 | ```` ``` ```` 로 열고 닫지 않아 아래 글이 모두 코드로 보임 | 고칠 것 |
| `{{{` 가 닫히지 않음 / 짝 없는 `}}}` | 접기·위키 블록의 여닫는 짝이 맞지 않음(중첩도 센다) | 고칠 것 |
| 각주가 닫히지 않음 | `[* ...` 에 닫는 `]` 가 없음(안에 `[[링크]]`·`[br]` 이 있어 엉뚱한 곳에서 끝난 경우 포함) | 고칠 것 |
| 수식이 닫히지 않음 | 한 줄에서 수식 여는 표시(백슬래시+`(`)가 닫는 표시보다 많음 | 고칠 것 |
| 제목의 `=` 개수가 다름 | `== 제목 =` 처럼 앞뒤 개수가 달라 제목 글자에 `=` 가 섞여 보임 | 고칠 것 |
| 없는 문서 링크 | `[[문서]]` 의 문서가 없음(눌러서 만들 수 있어서 일부러 둔 것일 수도 있다) | 참고 |
| 속성·회차가 없는 인물 / 이름이 같은 인물 | 인물 문서(인물 3명 이상)에서 `특기:값`·회차 줄이 하나도 없는 인물, 같은 이름이 또 있는 인물. 일반 문서에는 나오지 않는다 ([`character-table.md`](character-table.md)) | 참고 |

## 쓰는 법

1. 점검할 문서를 연다.
2. 메뉴 **편집 > 문서 점검**을 누른다.
3. 목록에서 항목을 누르면 창이 닫히고 편집기가 그 줄로 이동한다(뷰어 모드였다면 듀얼 모드로 바뀐다).
4. 고친 뒤 다시 열어 문제가 사라졌는지 본다. Esc 로 닫는다.

- 코드블록 안과 한 줄 안의 `` `코드` ``·`{{{ 코드 }}}` 안은 점검하지 않는다(코드 속 `{{{` 를 오류로 알리지 않으려고).
- 열린 문서가 없으면 "점검할 문서가 열려 있지 않습니다"가 보인다.

## 실제 문서로 확인한 것

작업 폴더 문서 10,796개를 읽기만 해서 돌려 보았다(약 5초). 문제가 나온 문서는 5개이고, 실제 실수는 제목 `=` 개수가 다른 2곳과 닫히지 않은 `{{{#red` 1곳이다(나머지 2곳은 상용구 파일 속 코드 조각). 처음에는 일반 괄호까지 수식으로 오해해 32곳이 잘못 나왔고 고쳤다.

## 구조

- `src/lib/docCheck.js`: 점검 규칙(순수 함수 `checkDocument`, 없는 링크 모으기 `findMissingLinks`). 글 속 코드 판단은 `src/lib/inlineCode.js` 와 같다.
- `src/components/DocCheckModal.jsx`: 목록 창. 없는 링크는 뷰어와 같은 변환기로 그려 `wiki-link-missing` 에서 모은다.
- `electron/main.js`(메뉴) -> `electron/preload.cjs`(`onMenuOpenDocCheck`) -> `src/App.jsx`(창 열기).
- 시험: `tests/lib/docCheck.test.js`, `tests/electron/docCheckMenu.test.js`.

## 알려진 한계

- 한 문서만 점검한다. 작업 폴더 전체 점검은 아직 없다.
- 표 줄의 칸 수 불일치, 닫히지 않은 `<table>` 표시 같은 것은 찾지 않는다.
- 줄에 걸친 수식(`$$`) 점검은 하지 않는다(수식 여는 표시는 한 줄 안에서만 센다).

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| 코드블록 | ```` ``` ```` 로 감싼 여러 줄 코드 |
| 각주 | 본문 아래 번호로 모여 보이는 덧붙임 글 `[* 내용]` |
| 짝 | 여는 표시와 닫는 표시가 하나씩 맞는 것 |
| 오탐 | 문제가 아닌데 문제라고 알리는 것 |

# 상용구 단축어의 대소문자 구분

## 한 줄 요약

`MYSQL` 과 `mysql` 을 각각 다른 상용구로 등록할 수 있고, 스페이스바 자동 치환·Alt+Enter 는 친 글자와 **대소문자까지 같은** 단축어에만 반응한다.

## 사용 예

| 단축어 | 본문 |
|---|---|
| `MYSQL` | `MySQL` |
| `mysql` | `MySQL` |

`mysql` 을 치고 스페이스를 누르면 `mysql` 상용구가, `MYSQL` 을 치고 누르면 `MYSQL` 상용구가 `MySQL` 로 바뀐다. `Mysql` 처럼 등록하지 않은 대소문자 조합은 바뀌지 않는다.

## 동작

- **자동 치환(스페이스바)·수동 치환(Alt+Enter)**: 대소문자를 **구분**한다. 단축어가 길이가 다르게 여럿 겹치면 가장 긴 것이 이기는 규칙은 그대로다.
- **타이핑 중 추천 팝업**: 대소문자를 구분하지 않고 앞부분이 같은 단축어를 찾는다(소문자로 쳐도 `MySQL` 같은 단축어를 추천). 다만 친 글자와 대소문자까지 같은 단축어를 먼저 보여 준다(단, 폴더의 `_순서.txt` 에 적힌 단축어는 목록에 없는 단축어보다 항상 위다).
- **저장**: 대소문자만 다른 단축어끼리 서로 덮어쓰지 않는다 (아래 "원인" 참고).

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| **대소문자 구분** | `A` 와 `a` 를 다른 글자로 보는 것. 구분하지 않으면 같은 글자로 본다. |
| **단축어** | 상용구를 불러내는 짧은 이름. 이 앱에서는 상용구 파일의 이름이기도 하다. |
| **접두사(앞부분) 일치** | 단축어가 내가 친 글자로 "시작"하는 경우. 추천 팝업이 쓴다. 자동 치환은 끝까지 똑같아야 한다. |

## 원인 — 왜 `mysql` 이 등록되지 않았나

상용구는 "단축어 = 파일 이름"(`.wikidesk-snippets/폴더/단축어.md`)으로 저장된다. **Windows 는 파일 이름의 대소문자를 구분하지 않아서** `MYSQL.md` 와 `mysql.md` 를 같은 파일로 본다. 그래서 `mysql` 을 등록하면 이미 있던
`MYSQL.md` 를 열어 내용을 덮어썼고, 목록에는 하나만 남았다. 또 에디터의 치환도 대소문자를 가리지 않고 찾아서 구분 자체가 불가능했다.

## 저장 방식

- **평소에는 단축어를 그대로 파일 이름으로 쓴다.** 예전에 등록한 상용구와 호환된다.
- **같은 폴더에 대소문자만 다른 이름이 이미 있을 때만**, 새 단축어의 영문자를 `%XX` 로 인코딩해서 저장한다. 예: `MYSQL.md` 가 있는 폴더에 `mysql` 을 등록하면 `%6D%79%73%71%6C.md`. 앱 화면에는 입력한 그대로(`mysql`) 보인다.
- 인코딩된 이름에는 영문자가 글자 그대로 남지 않으므로 어떤 이름과도 대소문자로 겹치지 않는다. `É` / `é` 같은 영문 아닌 대소문자는 `%uXXXX` 로 저장한다.
- 이미 있는 단축어를 다시 등록하면 (일반 이름이든 인코딩 이름이든) 그 파일을 그대로 쓴다. 같은 단축어 파일이 두 개 생기지 않는다.
- 이 인코딩 이름을 탐색기에서 직접 바꾸면 단축어도 바뀐다. 이름을 바꾸려면 앱의 상용구 모달에서 지우고 다시 등록하는 편이 안전하다.

## 구현 위치

- `electron/fileSystem.js` — `ensureSnippet`(충돌 피하기), `encodeSnippetFileName`/`decodeSnippetFileName`(인코딩·복원).
- `src/lib/snippetMatch.js` — 에디터의 상용구 찾기 규칙(`findExactSnippetMatch`: 대소문자 구분, `findSnippetQuery`: 추천 팝업).
- `src/components/EditorPane.jsx` — 위 함수를 부르는 얇은 연결부.
- 테스트: `tests/electron/snippetCase.test.js`(실제 디스크), `tests/lib/snippetMatch.test.js`.

## 알려진 한계

- 이전에 `MYSQL` 을 등록한 뒤 `mysql` 을 등록하려다 **덮어써진 내용은 복구되지 않는다.** `mysql` 은 새로 등록해야 한다.
- 예전의 대소문자 구분 없는 치환에 기대던 상용구(소문자로 쳐도 `MySQL` 단축어가 치환되던 동작)는 이제 같은 대소문자로 쳐야 치환된다. 추천 팝업에서는 여전히 대소문자 상관없이 고를 수 있다.

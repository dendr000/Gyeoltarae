# 뷰어의 연속 공백 보존

## 한 줄 요약

편집창에서 단어 사이를 **2칸 이상 띄워 쓰면 뷰어(보기·듀얼 화면)에서도 그 칸 수 그대로 벌어져 보인다.** 예전에는 몇 칸을 띄우든 뷰어에서는 한 칸으로 합쳐져 간격 정렬이 보이지 않았다.

````text
편집창:  컬럼명 IS NULL      컬럼 값이 NULL이면 참
         컬럼명 IS NOT NULL    컬럼 값이 NULL이 아니면 참
뷰어(전): 컬럼명 IS NULL 컬럼 값이 NULL이면 참             ← 한 칸으로 합쳐짐
뷰어(후): 컬럼명 IS NULL      컬럼 값이 NULL이면 참         ← 편집창과 같은 칸 수
````

## 원인

웹 화면(HTML)은 공백이 몇 칸 이어지든 **한 칸으로 합쳐서** 그린다. 이 앱은 문단의 글을 그대로 HTML 에 넣고 있어서, 편집창에서 간격을 맞춰 써도 뷰어에서 합쳐졌다. (코드블록은 공백을 그대로 보여 주는 `pre` 로 그려서 원래부터 문제가 없었다.)

## 동작 규칙

| 항목 | 규칙 |
|---|---|
| 대상 | 문단·제목·목록·각주 등 글 속의 **공백 2칸 이상** 이어진 곳. 한 칸 공백은 예전 그대로 |
| 코드블록(```, `{{{ }}}`) | 건드리지 않는다(이미 공백이 그대로 보인다) |
| 표 | 건드리지 않는다(셀 구분자 양옆 공백이 문법의 일부라서 기존 처리 유지) |
| 인라인 코드 | 이 앱에는 인라인 코드 문법이 없다. 한 줄짜리 `{{{...}}}` 는 코드가 아니라 일반 글로 처리되므로 이 안의 연속 공백도 보존된다 |
| 복사 | 뷰어에서 글을 복사하면 **일반 공백**이 칸 수 그대로 복사된다(`&nbsp;` 같은 다른 글자가 섞이지 않아 SQL 도구에 붙여 넣어도 안전) |
| 편집창·저장 파일 | 바뀌지 않는다. 화면에 그릴 때만 적용된다 |

## 눈에 띄는 변화

- 지금까지 우연히 넣은 두 칸 공백(문장 끝 뒤 등)이 뷰어에서 실제로 넓게 보이게 된다. 의도한 변화이지만 기존 문서의 모양이 조금 달라질 수 있다.
- 문단 줄 **맨 앞의 들여쓰기**(공백 2칸 이상)도 이제 보인다. 목록·인용 문법으로 해석되는 줄은 기존처럼 문법이 먼저 처리한다.

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| 공백 합침 | HTML 이 연속된 공백을 한 칸으로 줄여 그리는 기본 규칙 |
| `white-space: pre` | 공백을 합치지 않고 입력한 칸 수 그대로 그리라는 CSS 설정 |
| `&nbsp;` | "줄바꿈이 안 되는 공백" 글자(U+00A0). 일반 공백과 다른 글자라 복사해서 다른 곳에 붙이면 문제가 될 수 있어 쓰지 않았다 |
| 후처리 | 파서가 HTML 을 다 만든 뒤 마지막에 한 번 더 손보는 단계. 스마트 따옴표(`smart-quotes.md`)도 같은 방식이다 |

## 구현 위치

| 파일 | 역할 |
|---|---|
| `src/lib/preserveSpaces.js` | HTML 의 글(태그 사이)에서 2칸 이상 공백을 `<span class="wiki-spaces">` 로 감싼다. 태그 속성·코드블록·표는 건너뛰고, 두 번 적용해도 결과가 같다 |
| `src/lib/wikiParser.js` | `parseWikiText` 마지막에서 스마트 따옴표 다음에 호출 |
| `src/App.css` | `.wiki-spaces { white-space: pre; }` |
| `tests/lib/preserveSpaces.test.js` | 단위 시험 19개(재현 테스트 포함) |

## 알려진 한계

- 인라인 태그 하나를 사이에 두고 이어진 공백(`가 <b> 나`)처럼 서로 다른 글 조각에 걸친 공백은 합쳐서 세지 않는다.
- 블록 태그 사이의 공백뿐인 조각(HTML 모양을 맞추려고 들어간 들여쓰기)은 글이 아니므로 감싸지 않는다.
- 줄바꿈 표시로 긴 줄이 접힐 때, 공백 덩어리 위치에서 줄이 접히지 않고 덩어리가 한 줄에 남으려 한다(`pre` 의 성질). 아주 긴 공백 덩어리가 화면 너비를 넘을 수 있다.

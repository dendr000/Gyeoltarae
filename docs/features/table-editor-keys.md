# 표 편집기의 셀 키 이동 (Tab · Shift+Tab · Enter · Shift+Enter · Alt+Enter)

## 한 줄 요약

표 편집기에서 셀 안에 있을 때 **Tab** 은 오른쪽 셀로(행의 끝이면 아래 행의 첫 번째 셀로), **Enter** 는 바로 아래 셀로 이동하고(없으면 새 행을 만든다), **Shift+Enter** 는 셀 안에서 줄바꿈(`[br]`)을 넣는다.

## 동작

| 키 | 동작 |
|---|---|
| **Tab** | **오른쪽 셀**로. 행의 **마지막 셀**이면 **아래 행의 첫 번째 셀**로, 마지막 행의 마지막 셀이면 **새 행을 만들고** 그 행의 첫 번째 셀로 간다. (예전에는 행 끝의 삭제 버튼 `[−]` 로 포커스가 갔다) |
| **Shift+Tab** | Tab 의 반대. **왼쪽 셀**로, 행의 첫 번째 셀이면 **윗 행의 마지막 셀**로 간다. 표의 맨 처음 셀에서는 평소 포커스 이동에 맡긴다. 새 행은 만들지 않는다. |
| **Enter** | **같은 열의 바로 아래 셀**로. 마지막 행이면 **새 행을 만들고** 같은 열로 간다. |
| **Shift+Enter** / **Alt+Enter** | 셀 안에 `[br]` 을 넣는다(커서 자리에). 뷰어에서는 셀 안 줄바꿈으로 보인다. Alt+Enter 는 엑셀의 칸 안 줄바꿈과 같은 키다(0.120.0) |
| **F2** / **Ctrl+Enter** | 칸 -> "선택한 셀 내용" 큰 입력칸으로 건너가고, 한 번 더 누르면 원래 칸으로 돌아온다(칸 하나만 골랐을 때). 자세한 내용은 [table-editor-modal.md](table-editor-modal.md) |
| 그 밖의 Ctrl/Alt 조합 | 건드리지 않는다(평소 동작). |

이동 예 (3열 표):

````text
Tab:        (0,0) → (0,1) → (0,2) → (1,0) → (1,1) → (1,2) → 새 행 (2,0)
Shift+Tab:  (2,0) → (1,2) → (1,1) → (1,0) → (0,2) → ...
Enter:      (0,1) → (1,1) → (2,1) → 새 행 (3,1)
````

- 이동한 셀에서는 글자가 있으면 **커서가 맨 뒤**에 놓인다(전체 선택이 아님 — 이어서 쓰거나 고칠 수 있게).
- **병합된 셀**: Tab·Shift+Tab 은 다른 셀의 병합에 **가려진 칸을 건너뛴다**(입력칸이 없는 칸). Enter 는 세로로 병합된 셀(rowspan)에서 병합이 끝난 다음 행으로 가고, 아래 칸이 다른 셀의 병합에 가려져 있으면 그 칸을 덮고 있는 셀로 간다.
- **한글을 입력하는 중**(조합 중)의 Enter 는 글자를 확정하는 키라서 이동하지 않는다. 확정한 뒤 한 번 더 누르면 이동한다.
- **Fn+Enter·숫자패드 Enter 는 쓰지 않는다:** Fn 은 키보드 장치가 처리해서 프로그램에는 보이지 않고, Fn+Enter·숫자패드 Enter 가 앱에 그냥 Enter 로 오는 키보드가 있어서 구별할 수 없다(0.119.0 에서 숫자패드 Enter 를 시도했으나 그렇게 와서 소용이 없었다 — 0.120.0 에서 Alt+Enter 로 바꿈). 이 키들은 그냥 Enter(아래 칸 이동)와 같다.
- Shift+Enter 로 넣은 `[br]` 은 입력칸의 되돌리기(Ctrl+Z)로 지워진다.
- 아래쪽의 "선택한 셀 내용" 큰 입력칸에서는 Enter 가 평소처럼 줄바꿈이다(이 키 이동은 표의 셀 입력칸에만 적용).

## 글자 서식 단축키 (Ctrl+B · Ctrl+U)

칸 안에서 Ctrl+B 는 굵게, Ctrl+U 는 밑줄이다(글자를 골랐으면 그 글자만, 고르지 않았으면 Ctrl+B 는 칸 전체 굵게). 자세히는 [table-editor-modal.md](table-editor-modal.md).

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| **셀** | 표의 한 칸. |
| **`[br]`** | 문서 문법에서 "여기서 줄바꿈"을 뜻하는 표시. 표 칸 안에서는 그냥 Enter 를 칠 수 없어서 이걸 쓴다. |
| **병합** | 여러 칸을 하나로 합친 것. 가로 병합(colspan)은 옆 칸까지, 세로 병합(rowspan)은 아래 칸까지 한 셀이 차지한다. |

## 방향키로 칸 이동 (↑ ↓ ← →)

칸 입력창에 커서가 있을 때 **방향키로 이웃한 칸으로 이동**한다. 글자 안에서 커서를 움직이는 평소 동작을 해치지 않도록 방향마다 규칙이 다르다.

| 키 | 동작 |
|---|---|
| **↑ / ↓** | 항상 위/아래 칸으로 간다 |
| **←** | 커서가 글자의 **맨 앞**일 때만 왼쪽 칸으로 간다(글자 중간이면 평소처럼 커서만 움직임) |
| **→** | 커서가 글자의 **맨 뒤**일 때만 오른쪽 칸으로 간다 |
| **Shift+방향키** | 글자 선택이라 건드리지 않는다 |

- 글자를 **드래그해서 선택해 둔 상태**에서는 이동하지 않는다(선택을 풀려고 누르는 것일 수 있어서).
- 이동한 칸에서 **오른쪽으로 들어왔으면 커서가 글자의 맨 앞**에, 왼쪽·위·아래로 들어왔으면 맨 뒤에 놓인다.
- **표 끝**(맨 위에서 ↑, 맨 아래에서 ↓ 등)에서는 이동하지 않고 평소 동작에 맡긴다. Tab·Enter 와 달리 **새 행을 만들지 않는다**.
- **병합된 칸**: 가로 병합 칸에서 →는 병합이 끝난 다음 칸으로, 세로 병합 칸에서 ↓는 병합이 끝난 다음 행으로 간다. 가려진 칸으로 가게 되면 그 칸을 덮고 있는 칸으로 간다.
- 한글을 입력하는 중(조합 중)에는 이동하지 않는다.
- 구현: `src/lib/tableNav.js` 의 `arrowTarget`, `TableEditorModal.jsx` 의 `handleCellKeyDown`. 테스트: `tests/lib/tableNav.test.js`.

## 칸 구분 (색)

칸이 모달 바탕과 구분되어 보이도록 라이트·다크 모두 칸 전용 색(`--grid-line`, `--grid-cell`, `--grid-head`, `--grid-range`, `src/index.css`)을 쓴다.

- **일반 칸**: 모달 바탕보다 한 단계 밝거나 어두운 바탕 + 또렷한 테두리. 마우스를 올리면 테두리가 강조색이 된다.
- **헤더 칸**("첫 번째 행을 헤더로" 체크 시 첫 행): 강조색 바탕 + 굵은 글씨 + 아래쪽 굵은 강조 테두리.
- **지금 글을 치는 칸**: 강조색 테두리·바깥 고리.
- **Shift+클릭으로 고른 범위**: 칸 위에 강조색을 덧칠하고 테두리를 강조색으로 한다(칸에 정한 배경색 위에도 보인다).

## 구현 위치

- `src/lib/tableNav.js` — 이동할 셀 계산(`tabTarget`, `shiftTabTarget`, `enterTarget`, 병합 처리 포함).
- `src/components/TableEditorModal.jsx` — 셀 입력칸의 키 처리(`handleCellKeyDown`), 새 행을 만든 직후 포커스(`pendingFocusRef` + 효과), Shift+Enter 는 `execCommand('insertText')` 로 넣어서 되돌리기가 이어지게 함.
- 테스트: `tests/lib/tableNav.test.js`. 화면 동작은 실제 키 입력으로 확인했다(3열 표에서 Tab 이 `(0,0) → (0,1) → (0,2) → (1,0)`, 마지막 행 끝에서 새 행, Shift+Tab 이 행 처음에서 윗 행 마지막 셀로, Enter 이동, Shift+Enter 가 `줄1[br]줄2`).

## 변경 이력 — Tab 을 처음에 잘못 만들었던 일

처음(0.75.0)에는 요청의 "`[−]` 가 아니라 아래 행의 첫 번째 셀로"를 **"Tab 은 어디서 누르든 아래 행의 첫 셀"** 로 읽어서 만들었다. 그래서 오른쪽에 셀이 있는데도 바로 아래 행으로 내려갔다. 요청의 뜻은 **행의 끝에서** 삭제 버튼이 아니라 아래 행의 첫 셀로 가라는 것이었고(오른쪽 셀 이동은 당연한 전제), 0.75.1 에서 바로잡았다. 이때 Shift+Tab 도 같이 맞췄다.

## 알려진 한계

- 방향키 이동은 칸 입력창 안에서만 된다(칸을 고른 상태가 아니라 글자를 치는 상태). 표 끝에서는 이동하지 않는다.

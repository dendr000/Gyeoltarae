# 시작 속도와 폴더 감시기

## 한 줄 요약

앱을 켜면 **화면이 먼저 뜨고**, 폴더 감시기는 첫 색인이 끝난 뒤 **사용자가 3초 입력하지 않는 틈에** 뒤에서 켜진다. (상용구가 4천여 개인 작업 폴더에서 클릭할 수 있기까지 15초 걸리던 문제를 고친 것)

## 배경 (왜 느렸나)

- 앱은 켜질 때 작업 폴더의 문서·상용구 파일을 **하나씩** 읽어 검색·링크·분류 색인을 만든다. 4,222개를 읽는 데 단독으로는 약 0.4초다.
- 같은 때에 **폴더 감시기**(바깥에서 파일이 바뀌면 앱에 알려 주는 기능, chokidar)도 켜졌다. 감시기는 켜자마자 작업 폴더의 파일 4,259개를 전부 훑는다(단독으로 약 8~9초).
- 둘이 메인 프로세스의 같은 처리 줄을 써서 서로 늦췄다. 파일 읽기 요청이 감시기 작업 뒤에 줄을 서서 **0.4초가 약 10초**가 됐다. 상용구 설치 기능으로 파일이 4천 개로 늘면서 눈에 띄게 됐다.

(측정: 2026-10-14, 실제 작업 폴더를 읽기만 하는 스크립트로. 실행 중인 exe 로 처음부터 끝까지 잰 것은 아니다.)

## 동작

1. 앱이 마지막 작업 폴더를 기억해 열면, 메인 프로세스는 감시기를 **켜지 않고** 폴더만 기억한다.
2. 화면이 첫 색인(문서 읽기)을 끝내면(실패해도) 메인에 "끝났다"고 알린다(`workspace:watch`).
3. 메인은 **마지막 입력(키보드·마우스)에서 3초 뒤**에 감시기를 켠다. 계속 입력 중이어도 알림에서 **20초**가 지나면 켠다.
4. 파일 삭제·이름 바꾸기·이동 뒤에 감시기를 다시 켜는 것도 같은 규칙을 쓴다(예전에는 그때마다 바로 켜서 몇 초씩 느려질 수 있었다).
5. 기다리는 사이에 다른 작업 폴더로 바꾸면 옛 폴더 예약은 버린다.

## 달라진 점과 한계

- 켜기 전 몇 초(보통 3초)에 바깥 프로그램이 작업 폴더의 파일을 바꾸면 앱이 즉시 알아채지 못한다. 앱 안에서 하는 작업은 앱이 직접 갱신하므로 영향이 없다.
- 감시기는 켜진 뒤 8초 남짓 뒤에서 폴더를 훑는다. 이 동안 단일 동작(저장, 문서 열기)은 영향이 거의 없다.

## 관련 파일

| 파일 | 역할 |
|---|---|
| `electron/watchScheduler.js` | "언제 켜는가" 규칙(입력 3초 쉼, 최대 20초 대기). 시간 함수를 받아서 가짜 시계로 시험한다 |
| `electron/main.js` | 스케줄러 생성, 창 입력 전달(`input-event`), `workspace:watch` 처리 |
| `electron/preload.cjs` | 화면에 `watchWorkspace` 노출 |
| `src/store/useAppStore.js` | `loadWorkspace` 가 첫 색인 뒤에 `watchWorkspace` 를 부름 |
| `tests/electron/watchScheduler.test.js` | 규칙 시험 11개 + 시작 경로에서 감시기를 직접 켜지 않는지 소스 점검 5개 |

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| 폴더 감시기 | 폴더 안의 파일이 만들어지거나 바뀌거나 지워지면 프로그램에 알려 주는 부품. 바깥 프로그램으로 문서를 고쳐도 앱 목록이 갱신되게 한다 |
| 색인 | 검색·링크·분류를 빠르게 하려고 미리 모든 문서를 읽어 만들어 두는 목록 |
| 메인 프로세스 | Electron 앱에서 파일 접근 같은 일을 맡는 뒷 프로그램. 화면(렌더러)과 요청·응답(IPC)을 주고받는다 |
| IPC | 화면과 메인 프로세스가 주고받는 요청·응답 통로. 파일 하나 읽을 때마다 한 번씩 왕복한다 |
| 유휴(idle) | 사용자가 아무 입력도 하지 않는 상태 |

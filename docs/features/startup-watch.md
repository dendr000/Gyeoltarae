# 시작 속도와 폴더 감시기

## 한 줄 요약

앱을 켜면 **화면이 먼저 뜨고**, 폴더 감시기는 첫 색인이 끝난 뒤 **사용자가 3초 입력하지 않는 틈에** 뒤에서 켜진다. (상용구가 4천여 개인 작업 폴더에서 클릭할 수 있기까지 15초 걸리던 문제를 고친 것)

## 배경 (왜 느렸나)

- 앱은 켜질 때 작업 폴더의 문서·상용구 파일을 **하나씩** 읽어 검색·링크·분류 색인을 만든다. 4,222개를 읽는 데 단독으로는 약 0.4초다.
- 같은 때에 **폴더 감시기**(바깥에서 파일이 바뀌면 앱에 알려 주는 기능, chokidar)도 켜졌다. 감시기는 켜자마자 작업 폴더의 파일 4,259개를 전부 훑는다(단독으로 약 8~9초).
- 둘이 메인 프로세스의 같은 처리 줄을 써서 서로 늦췄다. 파일 읽기 요청이 감시기 작업 뒤에 줄을 서서 **0.4초가 약 10초**가 됐다. 상용구 설치 기능으로 파일이 4천 개로 늘면서 눈에 띄게 됐다.

(측정: 2026-10-14, 실제 작업 폴더를 읽기만 하는 스크립트로. 실행 중인 exe 로 처음부터 끝까지 잰 것은 아니다.)

## 동작

1. 앱이 마지막 작업 폴더를 기억해 열면, 메인 프로세스는 감시기를 **켜지 않고** 폴더만 기억한다.
2. 화면이 첫 색인(문서 읽기)을 끝내면(실패해도) 메인에 "끝났다"고 알린다(`workspace:watch`).
3. 메인은 **마지막 입력(키보드·마우스)에서 3초 뒤**에 감시기를 켠다. 계속 입력 중이어도 알림에서 **20초**가 지나면 켠다.
4. 파일 삭제·이름 바꾸기·이동 뒤에 감시기를 다시 켜는 것도 같은 규칙을 쓴다(예전에는 그때마다 바로 켜서 몇 초씩 느려질 수 있었다).
5. 기다리는 사이에 다른 작업 폴더로 바꾸면 옛 폴더 예약은 버린다.

## 감시기를 별도 프로세스로 옮김 (2026-11-19)

문서가 1만 개(2.7GB)인 작업 폴더에서 **켠 지 20~25초 뒤 입력이 멈췄다**(한 글자에 최대 18초, 간헐적으로 65초까지). "계속 입력 중이어도 20초가 지나면 켠다"는 규칙 때문에 감시기가 입력 도중에 켜졌고, 감시기가 메인 프로세스 안에서 1만 개 파일을 훑는 동안 메인이 막혀 자동 저장·파일 읽기 요청이 줄을 섰기 때문이다.

- 감시기(chokidar)를 메인이 아니라 **Electron 의 별도 작업 프로세스(utilityProcess)**에서 돌린다. 그 프로세스가 아무리 바빠도 메인과 화면은 막히지 않는다.
- 바뀐 파일은 작업 프로세스가 메인에 메시지로 알리고, 메인이 화면에 그대로 전달한다(화면 쪽은 변화 없음).
- 감시를 끌 때(삭제·이름 변경·이동 직전)는 작업 프로세스를 **끝내고 완전히 끝난 뒤** 진행한다. 윈도우가 폴더 핸들을 확실히 놓으므로 예전의 삭제 충돌(ENOTEMPTY) 방지에 더 확실하다.
- "언제 켜는가" 규칙(입력 3초 쉼, 최대 20초)은 그대로 둔다. 이제 20초에 강제로 켜져도 입력이 멈추지 않는다.
- 작업 프로세스가 저절로 죽으면 콘솔 로그에 남기고 다시 켜지 않는다(다음 감시 요청 때 새로 켜진다).

측정(실제 작업 폴더 10,796개, 패키지한 exe, 0.25초마다 한 글자씩 70초 입력):

| | 최대 지연 | 70초 입력 중 |
|---|---|---|
| 고치기 전 | 18.3초 | 26~45초 구간에 멈춤, 45~65초 간헐적 지연 |
| 고친 뒤(2·3회째) | 0.08초 / 0.07초 | 글자당 평균 약 40~50ms, 150ms 넘는 것 없음 |

고친 뒤 첫 실행에서는 0~60초 사이 글자당 0.3~0.8초(최대 1.7초) 느렸다. 새로 만든 exe 를 처음 켤 때의 디스크 검사·캐시 때문으로 보이며(이후 실행에서는 재현되지 않음) 멈춤(수 초~18초)은 없었다. 또 외부에서 만든 문서가 켠 지 30초 뒤에도 목록에 나타나고 지우면 사라지는 것을 실제 exe 에서 확인했다.

## 달라진 점과 한계

- 켜기 전 몇 초(보통 3초)에 바깥 프로그램이 작업 폴더의 파일을 바꾸면 앱이 즉시 알아채지 못한다. 앱 안에서 하는 작업은 앱이 직접 갱신하므로 영향이 없다.
- 감시기는 켜진 뒤 8초 남짓 별도 프로세스에서 폴더를 훑는다. 이 동안에도 입력·저장·문서 열기는 막히지 않는다.
- 감시 작업 프로세스는 메모리를 조금 더 쓴다(프로세스가 하나 늘어난다).

## 관련 파일

| 파일 | 역할 |
|---|---|
| `electron/watchScheduler.js` | "언제 켜는가" 규칙(입력 3초 쉼, 최대 20초 대기). 시간 함수를 받아서 가짜 시계로 시험한다 |
| `electron/watchProcess.js` | 감시 작업 프로세스를 켜고 끄고(끝날 때까지 기다림) 이벤트를 전달하는 래퍼. 가짜 프로세스로 시험한다 |
| `electron/watchWorker.js` | 별도 프로세스 안에서 chokidar 로 폴더를 감시하고 바뀐 파일을 부모에게 알린다 |
| `electron/watchIgnore.js` | 감시에서 뺄 경로 규칙(점 파일·node_modules 제외, 분류·사전 등 내용 폴더는 포함) |
| `electron/main.js` | 스케줄러·감시 프로세스 생성, 창 입력 전달(`input-event`), `workspace:watch` 처리 |
| `electron/preload.cjs` | 화면에 `watchWorkspace` 노출 |
| `src/store/useAppStore.js` | `loadWorkspace` 가 첫 색인 뒤에 `watchWorkspace` 를 부름 |
| `tests/electron/watchScheduler.test.js` | 규칙 시험 11개 + 시작 경로에서 감시기를 직접 켜지 않는지 소스 점검 5개 |
| `tests/electron/watchProcess.test.js` | 제외 규칙 5개 + 래퍼 10개 + 메인이 chokidar 를 직접 쓰지 않는지 소스 점검 2개 |

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| 폴더 감시기 | 폴더 안의 파일이 만들어지거나 바뀌거나 지워지면 프로그램에 알려 주는 부품. 바깥 프로그램으로 문서를 고쳐도 앱 목록이 갱신되게 한다 |
| 색인 | 검색·링크·분류를 빠르게 하려고 미리 모든 문서를 읽어 만들어 두는 목록 |
| 메인 프로세스 | Electron 앱에서 파일 접근 같은 일을 맡는 뒷 프로그램. 화면(렌더러)과 요청·응답(IPC)을 주고받는다 |
| IPC | 화면과 메인 프로세스가 주고받는 요청·응답 통로. 파일 하나 읽을 때마다 한 번씩 왕복한다 |
| utilityProcess | Electron 이 제공하는 별도 작업 프로세스. 앱 본체와 따로 돌아서 무거운 일을 해도 본체가 안 막힌다 |
| 유휴(idle) | 사용자가 아무 입력도 하지 않는 상태 |

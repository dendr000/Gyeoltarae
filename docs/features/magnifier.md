# 돋보기 (마우스 휠 클릭)

## 한 줄 요약

돋보기는 두 가지다. ① **둥근 돋보기**: 휠을 한 번 누르면 마우스를 따라다니며 둘레를 키운다. ② **영역 확대창**: 휠을 누른 채 끌어 고른 사각형을 창 한가운데에 크게 보여 준다(아래 "영역 확대창").

**둥근 돋보기: 마우스 휠(가운데 버튼)을 한 번 누르면 마우스 위치를 중심으로 둥근 돋보기가 떠서 그 둘레를 키워 보여 주고, 한 번 더 누르면 꺼진다.** 돋보기가 켜진 동안 **휠을 굴리면 배율이 바뀌고**, 크기는 메뉴 **설정 > 돋보기 크기**에서 4단계로 고른다. 돋보기는 마우스 입력을 가로채지 않아서 **클릭·마우스 오버·드래그·입력이 그대로 동작**하고, 팝업·메뉴·창의 글자도 키워서 보인다.

## 쓰는 법

| 동작 | 결과 |
|---|---|
| 휠 클릭(누르고 바로 뗌) | 켜짐. 마우스 자리가 돋보기의 한가운데가 된다 |
| 마우스 움직이기 | 돋보기가 마우스를 따라간다(마우스가 늘 중심) |
| 휠 위로 굴리기 | 확대(눈금 하나마다 1.2배) |
| 휠 아래로 굴리기 | 축소 |
| 휠 클릭 한 번 더 / `Esc` | 꺼짐(영역 확대창이 떠 있을 때도 같다) |
| 휠을 **누른 채 끌기** | 영역 확대창(아래) |
| 왼쪽 클릭·오른쪽 클릭·드래그·입력 | 평소처럼 진짜 화면에 들어간다 |

- 배율은 **1.5배 ~ 8배**이고 처음에는 2.5배다. 휠로 바꾼 배율은 돋보기를 껐다 켜도 이어진다(앱을 다시 켜면 처음 값).
- 돋보기가 켜진 **동안에는 휠이 문서를 스크롤하지 않고 배율만 바꾼다.** 문서를 스크롤하려면 돋보기를 끄고 한다.
- 휠 클릭에 원래 붙어 있는 윈도의 **자동 스크롤**(클릭하면 마우스를 움직여 끌려가는 것)과 링크의 **새 창 열기**는 막아 둔다.

## 영역 확대창 (휠을 누른 채 끌기)

휠을 누른 채 마우스를 끌면 **점선 사각형**이 그려지고, 휠에서 손을 떼면 그 영역이 **창 한가운데에 크게** 뜬다. 큰 화면에서 작은 글씨 한 곳을 오래 볼 때 쓴다.

| 동작 | 결과 |
|---|---|
| 휠을 누른 채 끌고 떼기 | 그 영역을 창의 92% 안에서 가득 차게(최대 8배) 키운 확대창이 한가운데에 뜬다 |
| 확대창 위에서 휠 굴리기 | 영역 한가운데를 기준으로 확대/축소(눈금 하나 1.2배, 1.1~8배) |
| 확대창 안에서 클릭·더블클릭·오른쪽 클릭 | 진짜 화면의 **같은 자리**로 전달되어 단추·링크·탭·메뉴가 눌린다 |
| 확대창 위에 마우스 올리기 | 진짜 화면의 그 자리 요소에 마우스 오버가 전달되고, 오버 색도 확대창에 보인다 |
| 입력 칸(편집창 등)을 클릭하고 글 쓰기 | 진짜 입력 칸에 포커스가 가고 **눌린 자리에 캐럿이 놓인 채** 글이 입력된다. 입력하는 글이 확대창에도 바로 보인다 |
| 휠 클릭 한 번 / `Esc` | 확대창이 닫힌다 |

- 사각형이 가로·세로 24px 보다 작으면 실수로 끈 것으로 보고 무시한다. 휠을 누른 자리에서 6px 이하만 움직이면 "끌기"가 아니라 "클릭"으로 본다(그냥 켜기/끄기).
- 영역 확대창은 마우스를 받는다. 영역이 마우스 자리가 아니라 창 한가운데에 떠 있어서, **확대창 안의 마우스 동작을 진짜 화면의 같은 자리로 대신 전달**하기 때문이다(`src/lib/magnifierForward.js`).
- 복제본(확대창 안의 그림)은 **입력을 받지 않는다**(`inert`). 복제본 안의 입력 칸이 포커스를 가져가 글이 엉뚱한 곳에 들어가는 일을 막으려는 것이다. 키보드는 진짜 입력 칸이 받는다.
- 확대창 안에서 **글을 드래그해 선택하기, 입력 칸 안에서 드래그로 범위 선택하기는 되지 않는다**(코드가 보낸 클릭으로는 브라우저가 글 선택을 하지 않는다). 선택하려면 확대창을 닫고 한다. (키보드는 진짜 입력 칸이 받으므로 글 입력은 된다. 키보드로 범위를 선택하는 것은 시험해 보지 않았다.)
- 팝업이 확대 영역 **밖**에 뜨면(오른쪽 클릭 메뉴 등) 확대창에는 보이지 않는다. 영역 안에 뜨면 키워서 보인다.

## 크기 선택

메뉴 **설정 > 돋보기 크기**(하위 메뉴, 하나만 고르는 라디오)에서 **둥근 돋보기**의 지름을 고른다. 영역 확대창의 크기는 끈 영역이 정한다.

| 단계 | 지름 |
|---|---|
| 작게 | 160px |
| **보통(기본)** | 240px |
| 크게 | 340px |
| 아주 크게 | 460px |

- 고른 값은 이 PC 의 앱 설정 파일(`config.json`)의 `magnifierSize`(`small`·`normal`·`large`·`xlarge`)에 저장되어 **다음 실행에도 유지**된다. 값이 없거나 이상하면 보통으로 본다.
- 돋보기가 켜진 채로 크기를 바꾸면 바로 반영된다.

## 클릭·마우스 오버가 되는 이유

돋보기는 **마우스 입력을 받지 않는 그림층**이다(`pointer-events: none`). 마우스가 돋보기를 뚫고 아래의 진짜 화면에 닿는다. 그리고 돋보기의 확대 중심이 마우스 위치이므로, **돋보기 한가운데에 보이는 것이 곧 마우스 바로 아래의 진짜 요소**다. 그래서 따로 흉내 낼 필요 없이 클릭, 마우스 오버(툴팁 포함), 드래그가 진짜 화면에서 일어난다. 그 결과로 화면이 바뀌면(툴팁이 뜨거나 메뉴가 열리거나 글을 치면) 돋보기도 따라서 바뀐다.

## 만들어진 방식

1. 켜는 순간 앱 화면(`body` 안 전체)을 **복제**해 둥근 창 안에 넣고, 마우스 위치가 창 한가운데에 오도록 옮긴 뒤 CSS 로 키운다. 그림(스크린샷)이 아니라 요소 복제라서 **키워도 글자가 선명**하다.
2. 복제본은 **shadow DOM** 안에 둔다. 앱이 `document.querySelector` 로 요소를 찾을 때 복제본의 요소가 섞이지 않게 하려는 것이다.
3. 앱 화면이 바뀌거나(`MutationObserver`), 스크롤·입력이 있으면 한 프레임에 한 번씩 복제본을 다시 만든다. 복제로는 안 따라오는 **입력 칸의 현재 글, 스크롤 위치, 체크 상태**는 따로 채워 넣는다.
4. 마우스 아래 요소에 닿는 `:hover` 효과(버튼이 밝아지는 것 등)는 복제본에 닿지 않으므로, 앱의 CSS 에서 `:hover` 규칙을 찾아 "복제본용 표시 클래스" 규칙으로 바꿔 두고 마우스 아래 요소(와 조상)에 그 표시를 붙인다.

| 파일 | 역할 |
|---|---|
| `shared/magnifier.js` | 크기 4단계·지름, 배율 범위·휠 한 눈금 계산(`nextZoom`), 돋보기 위치·복제본 변환 — 메인과 화면이 함께 쓰는 순수 함수 |
| `src/lib/magnifierDom.js` | `:hover` 규칙 바꾸기, 마우스 아래 요소 표시, 입력값·스크롤 채우기, 복제 만들기 |
| `src/lib/magnifierClone.js` | 앱 화면 복제본(shadow DOM)과 다시 만들기 감시 — 둥근 돋보기·영역 확대창이 함께 씀 |
| `src/lib/magnifierLens.js` | 마우스를 따라다니는 둥근 돋보기 |
| `src/lib/magnifierRegion.js` | 영역 확대창(창 한가운데에 뜨고 마우스 동작을 진짜 화면으로 전달) |
| `src/lib/magnifierForward.js` | 확대창 안의 마우스 동작을 진짜 요소에 보내는 규칙(대상 찾기·이벤트 만들기·포커스·캐럿·마우스 오버) |
| `src/components/Magnifier.jsx` | 휠 클릭·끌기 판정, 점선 사각형, 휠·`Esc` 처리, 크기 설정 반영 |
| `electron/settingsMenu.js`, `electron/main.js`, `src/store/useAppStore.js`, `src/lib/mockApi.js` | 메뉴 "돋보기 크기" 와 값(`magnifierSize`) 저장·전달 |
| `src/App.css` (`.magnifier-host`, `.magnifier-region`, `.magnifier-band`) | 둥근 모양·테두리·그림자·마우스 입력 무시, 영역 확대창(사각형·마우스 받음), 끄는 동안의 점선 사각형 |
| `tests/lib/magnifier.test.js`, `tests/lib/magnifierDom.test.js`, `tests/lib/magnifierForward.test.js`, `tests/electron/magnifierSetting.test.js` | 계산·복제 규칙·전달 규칙·설정·구조 시험 |

## 확인한 것 (실제 Electron 창, 실제 마우스 입력)

**둥근 돋보기** — 휠 클릭으로 켜면 한가운데가 마우스 자리와 일치(240px 돋보기) · 휠 위로 1번 2.5배에서 3배, 아래로 2번 2.08배 · 마우스를 사이드바 목록으로 옮기면 돋보기가 따라가며 그 목록 항목의 오버 색이 복제본에도 보임 · **돋보기가 켜진 채로 왼쪽 클릭해서 다른 문서가 열림** · 크기를 크게(340px)·작게(160px)로 바꾸면 켜진 돋보기에 바로 반영 · `Esc` 와 휠 클릭 한 번 더로 꺼짐 · 앱의 `document.querySelectorAll` 에 복제본이 섞이지 않음.

**영역 확대창** — 휠을 누른 채 끌면 점선 사각형이 보이고, 떼면 그 영역이 창 한가운데에 5.06배로 뜸 · 확대창 안의 "둘째" 항목에 마우스를 올리면 오버 색이 보임 · **확대창 안에서 "둘째" 를 클릭하면 진짜 화면에서 그 문서가 열림** · 휠 위로 5.06배에서 6.07배 · Esc 로 닫힘 · 10px 짜리 영역은 무시됨 · 편집 모드에서 확대창 안의 글을 클릭하면 진짜 편집창에 포커스가 가고 캐럿이 클릭한 자리에 놓이며(6번째 글자 뒤), "ZZ" 를 입력하면 진짜 편집창과 확대창 안의 글에 모두 반영됨 · 빌드한 exe 에서도 둥근 돋보기를 확인(스타일시트 `:hover` 규칙도 읽혀 오버 표시가 됨).

## 한계

- **앱 창 안의 화면만 키운다.** 운영체제가 그리는 것(창 맨 위 메뉴 막대, 파일 열기 창, 글자를 한글로 조합하는 중에 뜨는 변환창, 마우스를 올렸을 때 뜨는 기본 말풍선 `title`)은 키워지지 않는다.
- **돋보기가 마우스를 따라다녀서** 돋보기 가장자리에 보이는 요소를 곧바로 누를 수는 없다. 누르려는 요소를 돋보기 한가운데로 가져온 뒤 누른다(운영체제 화면 돋보기와 같은 방식).
- 복제본에는 **글자 선택(파란 하이라이트)과 깜빡이는 커서(캐럿)가 보이지 않는다.** 진짜 화면에는 있다.
- 복제본에서는 앱의 **포커스 테두리**(`:focus`)와 **누르는 중 효과**(`:active`)가 보이지 않고 마우스 오버(`:hover`)만 따라온다.
- 아주 긴 문서에서 글을 칠 때는 한 프레임마다 화면 복제를 다시 하므로 약간 느려질 수 있다.
- 영역 확대창에서는 글 **드래그 선택**이 되지 않는다(위 "영역 확대창" 참고).

## 용어 설명 (초보자용)

| 용어 | 뜻 |
|---|---|
| 돋보기 | 화면의 한 곳을 둥근 창 안에서 크게 보여 주는 도구 |
| 휠 클릭 | 마우스 가운데 휠을 굴리지 않고 눌러 딸깍 하는 것 |
| 영역 확대창 | 휠을 누른 채 끌어 고른 사각형을 창 한가운데에 크게 띄운 창 |
| inert | 마우스·키보드를 받지 않고 포커스도 못 받게 하는 설정 |
| 캐럿 | 글을 칠 자리를 알려 주는 깜빡이는 세로 막대 |
| 배율 | 몇 배로 키우는지. 2배면 가로세로 두 배 |
| 복제 | 화면을 그림으로 찍는 것이 아니라 화면 요소 전체를 똑같이 한 벌 더 만드는 것 |
| shadow DOM | 문서 안에 따로 격리된 작은 화면 영역. 바깥 문서의 검색에 안의 요소가 잡히지 않는다 |
| pointer-events: none | 마우스 클릭·이동을 받지 않고 그대로 아래로 통과시키는 설정 |
| 마우스 오버(hover) | 클릭하지 않고 마우스를 올려 두기만 한 상태 |

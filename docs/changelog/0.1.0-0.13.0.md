# 변경 내역 (보관) — 0.1.0 ~ 0.13.0

오래된 버전의 변경 내역이다. 최신 내역은 [`docs/CHANGELOG.md`](../CHANGELOG.md) 에 있다. 항목은 옮기기만 했고 고치지 않았다.

## [0.13.0] - 2026-09-14

### 수정 (중요)
- **exe를 완전히 껐다 켜면 새로 만든 폴더/문서가 사라지는 문제의 원인 발견 및 방지 장치 추가**: 실제 원인은 저장 로직이 아니라 워크스페이스 폴더의 "위치"였음. `WikiDesk.lnk` 바로가기의 실행 위치가 `release-packager\WikiDesk-win32-x64\`(exe가 들어있는 폴더)이다 보니, 워크스페이스 폴더 선택 대화상자가 처음엔 그 위치를 기본값으로 열었고, 그 안에(또는 바로 옆에) 테스트용 폴더를 만들기 쉬웠음. 그런데 이 폴더는 `npm run dist:win:packager`로 앱을 다시 빌드할 때마다(`@electron/packager`의 `overwrite: true` 옵션 때문에) 통째로 삭제되고 새로 만들어짐 — 즉 문서가 저장이 안 된 게 아니라, 앱을 재빌드/재설치할 때 워크스페이스 폴더 자체가 함께 삭제된 것
  - 이제 워크스페이스로 앱 설치 폴더 안쪽을 선택하면 경고와 함께 선택이 거부됨
  - 기존에 이미 앱 설치 폴더 안을 워크스페이스로 쓰고 있었다면, 다음 실행 시 경고 대화상자로 안전한 위치로 옮기라고 안내함
  - **문서·바탕화면 등 앱과 무관한 폴더를 워크스페이스로 다시 선택해 주세요.**

### 추가
- **F2 키 / 우클릭 메뉴로 이름 변경 및 삭제**: 지금까지는 더블클릭으로만 이름을 바꿀 수 있었는데, 탐색기처럼 문서·폴더 행을 선택한 뒤 F2를 누르거나 우클릭하면 뜨는 메뉴로도 이름 변경·삭제(폴더는 새 문서·새 폴더도)를 할 수 있음

## [0.12.0] - 2026-09-14

### 수정 (중요)
- **실제 exe에서 "새 문서"/"새 폴더"/"분류 추가"/"자료 불러오기"/"틀 불러오기" 등 이름을 입력받는 버튼이 전부 반응하지 않던 문제 수정**: 원인은 `window.prompt()` — Electron은 `alert()`/`confirm()`은 지원하지만 `prompt()`는 의도적으로 아예 구현하지 않음(공식 방침, 앞으로도 지원 계획 없음). 이 세션에서 만든 "이름을 입력하세요" 류 기능이 전부 이 함수를 썼기 때문에, 일반 브라우저 미리보기에서는 멀쩡히 동작하는 것처럼 보였지만 실제 exe에서는 호출하자마자 조용히 아무 일도 없이 끝나버렸음(그래서 버튼이 "반응 없는" 것처럼 보임)
  - 재사용 가능한 자체 입력 모달(`PromptModal`)을 새로 만들어 `window.prompt`를 쓰던 모든 곳(새 문서/새 폴더 이름, 분류 추가, 자료·틀 불러오기, 자료·틀 사이드바의 "+")을 교체함
  - 유형+이름처럼 두 번 연달아 묻던 것도 이제 필드 두 개가 있는 모달 하나로 한 번에 입력하도록 개선(새 문서 만들 때 글양식 선택도 이름 입력과 한 모달에서 같이 처리)
  - `window.confirm()`(삭제 확인 등)은 Electron에서 정상 동작하므로 그대로 유지

### 추가
- **폴더 이름 변경 지원**: 지금까지 문서(메모)는 더블클릭으로 이름을 바꿀 수 있었지만 폴더는 그런 기능이 아예 없었음 — 이제 폴더도 더블클릭하면 문서와 동일한 방식으로 이름을 바꿀 수 있고, 폴더 안의 하위 문서·폴더도 함께 옮겨짐. 더블클릭으로 이름을 바꿀 수 있다는 걸 알기 어려워서 문서·폴더 행에 마우스를 올리면 안내 문구(툴팁)도 추가함
- **미리보기(웹 브라우저) 모드의 폴더 이름 변경도 함께 수정**: `src/lib/mockApi.js`가 폴더 이름 변경 시 문서 확장자를 잘못 붙이던 문제와, 폴더 안의 하위 항목들을 함께 옮기지 못하던 문제를 고침

## [0.11.0] - 2026-09-14

### 수정
- **접기 문법(`{{{#!folding ...}}}`)이 나무위키 실제 문법과 다르게 동작하던 버그 수정**: 나무위키 공식 문법 도움말(나무위키:문법 도움말) 기준으로, 닫는 `}}}`가 내용 줄 끝에 바로 붙어도(`__내용__}}}`처럼, 꼭 그 줄에 단독으로 있지 않아도) 되는데, 기존 파서는 `}}}`가 반드시 단독 줄에 있어야만 블록이 닫히는 걸로 잘못 인식했음. 그 결과 이렇게 쓴 접기 블록이 문서 끝까지 계속 이어진 것으로 처리되어 버렸음. 표 셀 안 `{{{#!wiki}}}` 블록 처리(`mergeMultilineTableRows`)에는 이미 있던 중첩 깊이 계산 방식을 본문 파서에도 동일하게 적용해서 해결 — `{{{+1 ...}}}` 같은 중첩된 삼중괄호 문법이 안에 있어도 안전하게 처리됨
- **분류 출력명(`[[분류:이름|출력명]]`) 미지원 수정**: 나무위키처럼 분류 배지에 보이는 글자를 실제 분류명과 다르게 지정할 수 있음 — 분류 자체(멤버십·상위/하위 분류)는 항상 실제 이름 기준으로 유지되고, 배지에 보이는 글자만 바뀜
- 위 두 가지 모두 나무위키 공식 문법 도움말 문서를 직접 확인하고 비교해서 발견·수정함

## [0.10.0] - 2026-09-14

### 추가
- **틀 기능 — 실제 나무위키 문법 그대로 구현**: `{{틀:이름}}`, `{{틀:이름|매개변수=값|매개변수2=값2}}`(이름=값 또는 위치 인자 모두 가능), `[include(이름)]`, `[include(이름, 매개변수=값)]`
  - 틀 문서 안에서는 `{{{매개변수}}}`(기본값은 `{{{매개변수|기본값}}}`)로 전달받은 값을 그대로 사용 — 기존 `{{{+1 ...}}}`/`{{{#색상 ...}}}`/`{{{#!...}}}` 문법과 이름이 겹치지 않아 충돌 없음
  - 틀 호출은 문서 중간에 인라인으로 써도 되고, 표처럼 블록 요소를 담은 틀은 실제 나무위키처럼 중첩 틀 호출도 지원(틀이 다른 틀을 부르는 것도 가능)
  - 틀 문서 자체는 분류·자료와 마찬가지로 워크스페이스 트리와 분리된 전용 공간(`.wikidesk-templates`)에 저장되고, 사이드바에 "틀"이라는 별도 목록으로 표시됨. 아직 없는 틀을 호출하면 점선 테두리의 "없음" 표시가 뜨고 클릭해서 바로 만들 수 있음
  - "이 틀을 사용하는 문서" 역링크 목록 제공 (자료의 "참조하는 문서"와 동일한 방식)
  - 에디터 툴바에 "틀 불러오기" 버튼 추가
  - 기존 WikiDesk 전용 "자료" 카드 기능([[자료:유형/이름]])은 그대로 유지 — 틀은 임의 위키 문법 전체를 담는 범용 기능, 자료는 필드:값 형태의 가벼운 데이터 카드로 서로 다른 용도
- **글양식(새 문서 기본 양식)**: "틀"과는 별개 개념 — 새 문서를 만들 때 기존 틀 문서를 골라 그 내용을 한 번만 복사해 시작할 수 있음(매개변수는 기본값으로 채워짐). 틀 호출처럼 계속 연결되어 있는 게 아니라 그 순간의 내용을 그대로 복사해오는 것이라 이후 자유롭게 고쳐 써도 원본 틀에는 영향 없음. "+ 새 문서"로 만들 때 사용 가능한 틀 목록이 안내되고, 이름을 입력하면 그 틀로 시작하고 비워두면 기존처럼 빈 문서로 시작함

### 수정
- **미리보기(웹 브라우저, `npm run dev`) 모드에서 "+ 새 폴더"가 동작하지 않던 문제 수정**: `src/lib/mockApi.js`의 가짜 파일트리가 항상 모든 문서를 워크스페이스 바로 아래 평평하게만 두던 구조라, 폴더 생성 자체가 화면에 전혀 반영되지 않았음(실제 Electron 앱은 원래부터 정상 동작). 이제 미리보기 모드도 실제 파일시스템처럼 폴더가 중첩되고 빈 폴더도 유지됨
- **편집 화면에서 Ctrl+S를 누르면 브라우저의 "다른 이름으로 저장" 대화상자가 뜨던 문제 수정**: 문서는 이미 800ms 자동저장되지만, Ctrl+S 자체를 가로채서 그 자리에서 바로 저장하고 브라우저 기본 동작은 막도록 처리
- **프론트엔드 개발 서버 포트를 5173 → 3171로 변경**: `vite.config.js`, `electron/main.js`(Electron이 붙는 개발 서버 주소), `package.json`의 `electron:dev` 스크립트, `.claude/launch.json` 모두 반영

### UI
- **사이드바 접기/펼치기**: 사이드바와 본문 사이의 작은 화살표(‹ / ›)를 누르면 사이드바가 부드러운 애니메이션과 함께 닫히고 열림. 접혀 있어도 화살표는 그 자리에 계속 남아있어 언제든 다시 펼칠 수 있음

## [0.9.0] - 2026-09-14

### 추가
- **표 편집기 셀 병합·나누기**: 여러 셀을 Shift+클릭으로 범위 선택한 뒤 병합 버튼을 누르면 하나의 셀로 합쳐짐(왼쪽 위 셀의 내용·서식만 유지) — 실제 나무위키 문법(`<-N>` 가로 병합, `<|N>` 세로 병합)으로 저장됨. 병합된 셀은 나누기 버튼으로 다시 낱개 셀로 되돌릴 수 있음

  - 병합을 가로지르는 행/열을 삭제해도 안전하게 처리됨(걸쳐있는 병합은 자동으로 풀림)
  - 표 편집기에 "뷰어 미리보기" 추가 — 삽입될 문법 텍스트뿐 아니라 실제 뷰어처럼 병합된 셀이 어떻게 보이는지 바로 확인 가능

## [0.8.0] - 2026-09-14

### 추가
- **자료(데이터) 카드 — 나무위키 틀(템플릿) 기능의 WikiDesk식 대체**: 기술·특성처럼 여러 문서에서 반복해서 쓰는 정보를 한 곳에 저장해두고 다른 문서에서 불러와 쓸 수 있음
  - 자료는 `.wikidesk-data/유형/이름.md`(예: `기술/번개펀치.md`)에 저장되며, 내용은 `필드: 값` 형식 한 줄씩(고정 스키마 없음 — 기술은 타입/위력/설명, 특성은 설명만 등 자유롭게)
  - 다른 문서에서 그 줄에 단독으로 `[[자료:유형/이름]]`을 적으면 그 자리에 필드가 정리된 작은 정보 카드로 바로 렌더링됨(실시간 — 자료 문서를 고치면 이를 참조하는 모든 문서에 바로 반영됨)
  - 아직 만들어지지 않은 자료를 참조하면 점선 테두리의 "없음 — 클릭해서 만들기" 카드가 표시되고, 클릭하면 바로 만들 수 있음
  - 분류와 마찬가지로 워크스페이스 트리와 분리된 전용 공간 — 사이드바에 "자료"라는 별도 목록이 유형별로 묶여 표시되고, 각 자료를 참조하는 문서 목록(역링크)도 함께 보여줌
  - 에디터 툴바에 "자료 불러오기" 버튼 추가 ([[자료:유형/이름]] 삽입)

### 수정
- **비어있는 분류가 사라지지 않던 문제 수정**: 분류 태그를 모두 지워도 분류 설명 문서가 남아있으면 사이드바에 0개짜리 분류가 계속 남아있던 문제 — "분류" 사이드바 항목에 마우스를 올리면 나오는 × 버튼으로 설명 문서를 휴지통으로 보내 제거할 수 있음 (자료도 동일하게 삭제 가능)
- `[목차]` 박스의 항목 앞에 불필요하게 붙던 글머리 기호(•) 제거 — 이미 1./1.1. 번호가 붙어 있어 중복이었음

## [0.7.0] - 2026-09-14

### 추가
- **분류(카테고리) 페이지 기능 전면 지원**: 실제 나무위키 방식 그대로 구현
  - `[[분류:이름]]` 문법으로 아무 문서에나 분류를 지정 — 본문에서는 사라지고 문서 맨 아래에 클릭 가능한 분류 배지로 모임
  - 분류 배지를 누르면 그 분류의 **자동 생성 분류 페이지**로 이동: 상위 분류, (있다면) 손으로 쓴 설명 문서 내용, 하위 분류, 그리고 그 분류에 속한 문서 목록을 초성별로 묶어서 보여줌 (ㄱ~ㅎ → A~Z → 0~9 → 기타 순, 나무위키와 동일한 정렬 방식)
  - **분류 페이지는 일반 워크스페이스 문서 트리와 분리된 전용 공간**(`.wikidesk-categories` 폴더)에 저장됨 — 사이드바에 "분류"라는 별도 목록이 생겨 워크스페이스 트리를 어지럽히지 않고 모든 분류를 한눈에 보고 바로 이동할 수 있음. 분류 페이지에 직접 `[[분류:상위]]` 태그를 달면 그대로 상위 분류가 됨(분류의 분류 = 하위 분류 체계)
  - 아직 설명 문서가 없는 분류를 열람하면 "분류 설명 문서 만들기" 버튼으로 바로 생성 가능
  - 에디터 툴바에 "분류" 버튼 추가 ([[분류:이름]] 삽입)
  - 문서를 저장/생성/삭제/이름변경하거나 워크스페이스가 외부에서 변경될 때마다 분류 색인이 자동 갱신됨

## [0.6.0] - 2026-09-14

### 추가
- **표 테두리·행·열·표 전체 배경색**: 나무위키 실제 문법 확인 후 지원 — `<tablebordercolor=#색>`/`<tablebgcolor=#색>`/`<tablewidth=..>`/`<tablealign=left|center|right>`/`<tablecolor=#색>`(표 전체, 아무 셀에나 적어도 적용), `<rowbgcolor=#색>`(행 전체), `<colbgcolor=#색>`(그 열의 아래 행까지 이어짐), 셀 `<width>`/`<height>`
- **재사용 가능한 파스텔 색상 선택기**(`ColorPicker`) 신설 — 표준색 11개 + 파스텔~진한 톤 4단계 팔레트(회색 포함 12열) + 직접 선택(네이티브 피커) + "없음"(초기화). 표 편집기 배경색·글자색, 에디터 툴바 글자색, 그라데이션 편집기 색상 선택에 전부 적용
- **접을 수 있는 목차**: `[목차]`가 이제 네이티브 `<details>`로 렌더링되어 클릭으로 접고 펼 수 있음
- **제목 자동 번호 매기기**: `=제목=`/`==제목==` 등에 나무위키처럼 1., 1.1., 2. 형식 번호가 자동으로 붙음 (목차 항목에도 동일하게 반영)
- **우측 플로팅 목차**: 문서에 제목이 있으면 뷰어 오른쪽 가장자리에 작은 점들이 항상 표시되고, 마우스를 올리면 전체 목차가 펼쳐지며, 클릭하면 애니메이션 없이 즉시 해당 위치로 이동

## [0.5.0] - 2026-09-14

### 추가

## [0.4.0] - 2026-09-14

### 추가
- **표 셀 그라데이션 배경**: 나무위키 실제 문법 확인 후 지원 — 표 셀 안에 `{{{#!wiki style="..."}}}` 블록이 여러 줄에 걸쳐 들어가는 실제 구조를 그대로 파싱(`mergeMultilineTableRows`). 이중 색상 `{{{#글자색,#배경색 텍스트}}}`, `[br]` 줄바꿈도 함께 지원. 툴바에 "그라데이션 표" 버튼으로 바로 예시 삽입 가능
- **표 편집기 엑셀식 범위 선택**: Shift+클릭으로 사각 범위 선택 → 배경색·글자색·정렬을 선택 범위 전체에 일괄 적용
- **표 편집기 복사/붙여넣기**: Ctrl+C/V(또는 툴바 버튼)로 셀 범위를 서식 포함 복사·붙여넣기. 대상이 기존 그리드보다 크면 행/열 자동 확장. 외부(엑셀 등)에서 복사한 탭 구분 텍스트 붙여넣기도 지원(이 경우 서식 없이 텍스트만)

### 알려진 제한
- 표 셀 그라데이션은 시각 편집기(그리드)에서는 만들 수 없고 툴바의 "그라데이션 표" 삽입 후 직접 수정해야 함 (그리드 UI는 셀 하나가 통짜 스타일 블록이 되는 구조를 표현하기 어려움)

## [0.3.0] - 2026-09-14

### 수정
- **실행취소(Ctrl+Z) 버그**: 툴바 버튼이 React 상태를 직접 덮어써서 텍스트 영역의 네이티브 되돌리기 기록이 끊기던 문제. `document.execCommand('insertText', ...)`로 바꿔 실제 타이핑과 동일하게 되돌리기 스택에 쌓이도록 수정
- **글자색 미적용 버그**: `{{{#색상 텍스트}}}` 인라인 글자색이 내부적으로 `#`이 중복 처리되어 조용히 무시되던 문제 (표 배경색은 정상이었음). `safeColor()`가 `#` 유무 두 형식을 모두 정규화하도록 수정

### 추가
- 서식 툴바 디자인 개선: 단순 버튼 나열 → 아이콘(lucide-react) + 그룹별 구분선으로 재구성 (구조/서식/삽입 3그룹)
- '집중' 모드 이름을 '편집'으로 변경, 뷰어/듀얼/편집 모드는 헤더 정중앙에 배치
- `{{{#!wiki style="..."}}}` 자유 스타일 블록 추가 — 그라데이션·그림자·테두리 등 나무위키 심화 문법 지원. 위험한 속성(`position`, `url()`, `@import` 등)은 허용 목록 방식으로 원천 차단
- 표 편집기에 셀별 배경색·글자색·정렬(왼쪽/가운데/오른쪽) 컨트롤 추가 (셀을 선택하고 위쪽 미니 툴바로 적용, HWP/스프레드시트 방식). 기존 표를 열어 편집할 때도 이 속성들이 보존되도록 파싱 로직 확장
- 사이드바에 `.md`/`.txt` 파일 드래그 앤 드롭으로 새 문서 불러오기 추가 (`.hwp`/`.docx` 등 바이너리 포맷은 미지원 — 별도 파서 필요)

### 알려진 제한
- 표 편집기는 여전히 셀 병합을 마우스로 드래그해서 하는 기능은 없음 (병합은 기존처럼 문법을 직접 입력해야 함)
- 표 셀 안의 그라데이션은 지원하지 않음 (나무위키 자체에서도 셀 내부 그라데이션의 정확한 문법이 불확실해 임의로 구현하지 않음)

## [0.2.0] - 2026-09-14

### 추가
- 나무위키 문법 대폭 확장: `=제목=`(1~6단계), `'''굵게'''`/`''기울임''`, `^^위첨자^^`, `,,아래첨자,,`, 글자 크기(`{{{+1}}}`~`{{{+5}}}`/`{{{-1}}}`~`{{{-5}}}`), 글자색(`{{{#색상 ...}}}`), 목록(중첩 `*`, `1.`), 인용(중첩 `>`), 표 셀 확장 속성(가로/세로 병합, 정렬, 배경색 — 다중 스택 지원), 코드블록·접기(`{{{ }}}`, `{{{#!folding}}}`), 자동 목차(`[목차]`), 구분선 굵기 4단계, `[[문서명]]` 표시(클릭 이동은 2차)
- 기존 `#` 제목, `**굵게**`, `*기울임*`, `--취소선--`, `||=헤더=||`는 WikiDesk 전용 확장으로 유지 (진짜 나무위키 문법과 구분해서 README에 표로 정리 — 나무위키에 그대로 옮길 문서라면 진짜 문법 쪽을 쓰는 걸 권장)
- 표 편집기 모달: 에디터 툴바의 "표 편집기" 버튼으로 행/열 추가·삭제, 셀 편집, 헤더 행 토글(진짜 나무위키 `'''굵게'''`로 저장) 후 삽입. 커서가 기존 표 안에 있으면 그 표를 파싱해 편집 모드로 열고 확인 시 제자리에서 교체
- `npm run dist:win:packager`(`@electron/packager`) 빌드 시 프로젝트 루트에 `WikiDesk.lnk` 바로가기 자동 생성/갱신

### 알려진 제한
- 표 편집기로 기존 표를 열어 수정하면 셀의 고급 속성(병합/정렬/배경색)은 유지되지 않고 일반 텍스트로 단순화됨 (헤더 행 굵게 표시만 유지)

## [0.1.0] - 2026-09-14

### 추가
- 프로젝트 초기 구성 (Electron + React + Vite)
- 나무위키 스타일 커스텀 문법 파서 (`#` 제목, `**굵게**`, `__밑줄__`, `~~취소선~~`, `*기울임*`, `[* 각주]`, `||표||`, `#태그`)
- 헤더 중앙에 뷰어 / 듀얼 / 집중 3단 모드 전환 (듀얼 모드: 좌측 뷰어 · 우측 에디터)
- 워크스페이스 폴더의 `.md` 파일 트리 사이드바, 문서/폴더 생성·이름변경·삭제(휴지통 이동)
- 파일시스템 실시간 감시(chokidar) → 외부 편집 시 트리 자동 갱신
- 편집 중 800ms 디바운스 자동저장, 저장 상태 표시(저장 중/저장됨/저장 실패)
- 시스템 / 라이트 / 다크 화면 모드 토글 (localStorage에 기억)
- Electron 기본 메뉴(파일/편집/보기/창) 한글화
- 태그·제목 메타데이터를 위한 JSON 기반 로컬 인덱스 (`electron/metadataIndex.js`) — 향후 SQLite 등으로 교체 가능하도록 분리
- Windows exe 빌드 스크립트 (`npm run dist:win`, electron-builder)

### 알려진 이슈
- `npm run dist:win` (electron-builder)은 이 PC 환경에서 `EPERM: rename win-unpacked.tmp` 오류가 재현됨. 관리자 권한, Defender 예외 등록, 제어된 폴더 액세스 해제로도 해결되지 않았고, 순수 Node.js `fs.rename`으로도 동일하게 재현되어 electron-builder만의 문제가 아님을 확인함(원인 미상 — 검색 인덱싱/OneDrive 백업 등 백그라운드 프로세스의 디렉터리 핸들 점유로 추정).
- **대안으로 `npm run dist:win:packager`(`@electron/packager` 기반, `scripts/package-win.js`)를 추가** — 이 방식은 파일을 개별 복사해 통째 rename을 하지 않아 위 문제를 피해가며, 정상적으로 `release-packager\WikiDesk-win32-x64\WikiDesk.exe`가 생성되고 실행도 확인됨. 다만 nsis 설치파일이 아닌 포터블 폴더 형태만 생성함(폴더째로 압축해 배포).
